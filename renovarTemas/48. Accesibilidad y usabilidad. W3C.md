# **TEMA 48: ACCESIBILIDAD Y USABILIDAD. W3C. DISEÑO UNIVERSAL. DISEÑO WEB ADAPTATIVO.** 

## **<u>Accesibilidad y Usabilidad</u>** 

- <u>Accesibilidad</u> 

   - Definición: Facilitar el uso y acceso de la web a todas las personas, incluyendo aquellas con discapacidad (física, cognitiva, o tecnológica) 

   - Objetivo: Garantizar la universalidad de acceso a la web, independientemente de las habilidades o discapacidades de los usuarios. 

- <u>Usabilidad</u> 

   - Definición: Medida de la efectividad, eficiencia y satisfacción con la que un usuario puede lograr sus objetivos en un entorno determinado. 

   - Objetivo: Diseñar interfaces y sistemas que sean fáciles de usar y comprendidos por los usuarios. 

## **<u>W3C (World Wide Web Consortium)</u>** 

Objetivo: Establecer estándares y guiar el desarrollo web para asegurar su crecimiento sostenible y beneficio global. Principios: 

- <u>Web para todo el mundo: Hacer la web accesible para todas las personas,</u> independientemente de su hw, sw, idioma, cultura, ubicación o habilidades. 

- <u>Web desde cualquier dispositivo: Asegurar que la web sea accesible desde una</u> amplia variedad de dispositivos: computadoras, tabletas, teléfonos, etc. 

## **<u>W3C Web Accessibility Initiative (WAI)</u>** 

Es un comité integrado en el W3C, compuesto por instituciones públicas, privadas y empresariales a nivel mundial, que tiene como objetivo promover la accesibilidad en la web. Actualmente, WAI cuenta con varios grupos de trabajo clave: 

- **Accessibility Guidelines Working Group (AG WG)** : Desarrolla pautas para hacer los contenidos web accesibles, como las **WCAG** (Pautas de Accesibilidad al Contenido Web). 

- **Accessible Platform Architectures (APA)** : Revisa especificaciones, colabora con otros grupos y coordina estrategias para la accesibilidad dentro del W3C. 

- **Accessible Rich Internet Applications (ARIA)** : Desarrolla tecnologías para mejorar la accesibilidad de aplicaciones web interactivas. 

- **Education and Outreach Working Group (EOWG)** : Crea materiales educativos y de concienciación sobre la accesibilidad web. 

- **WAI Interest Group (WAI IG)** : Un grupo público que discute temas de accesibilidad web a través de listas de correo. 

## **<u>WCAG 2.1 (Web Content Accessibility Guidelines)</u>** 

- **Publicación y Evolución:** Las WCAG 2.1 fueron publicadas el 5 de junio de 2018 como una evolución de: 

   - **WCAG 2.0** (2008) 

   - **WCAG 1.0** (1999) 

- **Objetivo de WCAG 2.1** : mejorar la accesibilidad de tres grupos de usuarios: `o` Personas con discapacidad cognitiva o de aprendizaje. 

   - Personas con baja visión. 

   - Personas que acceden a la web desde dispositivos móviles. 

Estas pautas abordan las necesidades no cubiertas por WCAG 2.0, debido a los avances tecnológicos y cambios en la forma de acceder a la web. 

- **Principales Diferencias con WCAG 2.0** 

   - Se añadieron **17 nuevos criterios de conformidad** 

   - Se introdujeron nuevos términos en el glosario. 

   - Se agregaron pautas adicionales, como la **Modalidad de entrada** 

   - Se modificaron algunos criterios, como la referencia al color 

   - Se añadieron requisitos para **páginas completas** y **componentes opcionales** . 

- **Diferencia con WCAG 1.0** 

La principal diferencia es la **neutralidad tecnológica** , ya que las WCAG 2.0 y 2.1 son aplicables a todas las tecnologías web actuales y futuras, mientras que WCAG 1.0 solo cubría HTML y CSS. 

- **Principios Básicos:** Existen 4 principios fundamentales que deben seguir todas las pautas: 

   1. **Perceptible** : El contenido debe ser percibido por todos los usuarios (por ejemplo, alternativas textuales y subtítulos). 

   2. **Operable** : El contenido debe ser manejable mediante dispositivos de entrada (como teclado). 

   3. **Comprensible** : Los usuarios deben ser capaces de entender el contenido y su funcionamiento. 

   4. **Robusto** : El contenido debe ser compatible con tecnologías actuales y futuras. 

- **Pautas Específicas:** Las pautas se distribuyen en áreas clave para cada principio: `o` **Perceptible** : Proveer alternativas textuales, subtítulos, y contenido adaptable a tecnologías asistivas. 

   - **Operable** : Garantizar acceso mediante teclado, asegurar tiempo suficiente para interactuar con el contenido, evitar contenido peligroso y facilitar la navegación. 

   - **Comprensible** : Asegurar que el contenido sea legible y predecible, además de ayudar a prevenir y corregir errores. 

   - **Robusto** : Maximizar la compatibilidad con futuras tecnologías y aplicaciones. 

• **Criterios de Conformidad:** se clasifican en niveles A (menos exigente), AA y AAA (más exigente). Se usan para evaluar si un contenido cumple con las pautas de accesibilidad. Las **Pautas WCAG** (actualmente en su versión 2.1 y próximamente 2.2) definen **criterios de éxito** que permiten evaluar el grado de accesibilidad de un contenido web. Para determinar si un sitio es conforme, se utiliza un sistema de **niveles de conformidad** : 

- **Nivel A (mínimo o básico):** Requisitos fundamentales para que un sitio web sea accesible para algunos grupos de usuarios con discapacidad. Incluye criterios como: 

   - El contenido debe ser **navegable por teclado** . 

   - Las **imágenes** deben tener **texto alternativo** . 

   - **No se deben usar colores como único medio de transmisión de información** . 

- **Nivel AA (nivel recomendado para sitios públicos):** Requisitos que permiten un mayor grado de accesibilidad para una gama más amplia de usuarios. Incluye todo lo del nivel A **+** : 

   - **Contraste adecuado** entre texto y fondo (mínimo 4.5:1). 

   - Subtítulos para contenido multimedia grabado. 

   - Navegación **predecible** . 

   - Posibilidad de **redimensionar el texto** sin pérdida de funcionalidad. 

   - Formularios etiquetados de forma clara y accesible. 

Este nivel es el más utilizado y el exigido por normativas como la **EN 301 549** en Europa o la **Sección 508** en EE.UU. 

- **Nivel AAA (nivel máximo o avanzado):** Es el nivel más exigente y no siempre alcanzable para todos los sitios o contenidos. Incluye todo lo del nivel A y AA **+** : 

   - Contraste aún mayor (mínimo 7:1). 

   - Lenguaje más simple y comprensible. 

   - Traducciones a lengua de signos para vídeos. 

   - Apoyo para usuarios con discapacidades cognitivas (resúmenes, ayudas contextuales, etc.). 

Nota: **No se exige el cumplimiento total del nivel AAA** en la mayoría de las legislaciones. Se usa como objetivo voluntario o en sitios especializados. 

- **Declaración de conformidad (requisitos formales):** Para que un sitio web declare conformidad con las WCAG, debe: 

   1. **Cumplir todos los criterios de éxito** del nivel elegido (A, AA o AAA). 

   2. **Usar tecnologías web de forma accesible** (HTML, CSS, JavaScript, etc.). 

   3. **Indicar el alcance** de la conformidad (por ejemplo, todo el sitio, una sección específica). 

   4. **Especificar la versión de las WCAG utilizada** (2.0, 2.1…). 

   5. **Usar tecnologías que soporten la accesibilidad** (user agents, AT, etc.).

- **Técnicas de Éxito y Fallos Comunes** 

   - **Técnicas de suficiencia** : Garantizan el cumplimiento de los criterios. 

   - **Técnicas complementarias** : Mejoran la accesibilidad pero no garantizan el cumplimiento total. 

   - **Fallos comunes** : Errores conocidos que deben evitarse para no generar barreras de accesibilidad. 

- **Requisitos de Conformidad** 

Para que un contenido web sea conforme con WCAG 2.1 debe cumplir con los 5 requisitos principales, que incluyen garantizar el cumplimiento a nivel de páginas completas, uso de tecnologías compatibles con la accesibilidad, y no interferir con el acceso a otros contenidos. 

- **Declaración de Conformidad** 

Si una página cumple con las pautas, se puede incluir una declaración que indique el nivel de conformidad alcanzado (A, AA, AAA), la versión de las pautas y las tecnologías usadas en el contenido. 

## **<u>DISEÑO</u>** 

El **Diseño Universal** busca crear productos y entornos que sean fáciles de usar para el mayor número de personas, sin necesidad de adaptaciones especiales. Se aplica tanto a la arquitectura, ingeniería, como a las páginas web. Los principios clave del diseño son: 

- **Uso equitativo** : El diseño debe ser útil para personas con diversas capacidades. 

- **Uso flexible** : El diseño debe acomodarse a un rango amplio de preferencias y habilidades individuales. 

- **Simple e intuitivo** : El diseño debe ser fácil de entender, teniendo en cuenta la experiencia, conocimientos y habilidades del usuario. 

- **Información perceptible** : El diseño debe comunicar eficazmente la información necesaria, adaptándose a las condiciones sensoriales o ambientales del usuario. 

- **Con tolerancia al error** : El diseño debe minimizar los riesgos y consecuencias de acciones involuntarias. 

- **Que exija poco esfuerzo físico** : El diseño debe ser cómodo de usar con un mínimo esfuerzo físico. 

- **Tamaño y espacio adecuado** : El diseño debe proporcionar espacio adecuado para el acceso, manipulación y uso, teniendo en cuenta el tamaño del cuerpo y la movilidad del usuario. 

## **Tipos de Diseño Web** 

## 1. **Diseño Web Líquido o Fluido** 

Este tipo de diseño utiliza porcentajes en lugar de píxeles, lo que permite que los elementos se ajusten según el ancho de la pantalla. Aunque es adecuado para pantallas medianas (como ordenadores de escritorio o tablets), puede causar problemas en pantallas grandes (televisores) o pequeñas (móviles). Se considera menos recomendable debido a su impacto negativo en la usabilidad. 

## 2. **Diseño Web Adaptativo (AWD - Adaptive Web Design)** 

En este diseño se utilizan plantillas estáticas basadas en puntos de ruptura. Cuando la pantalla alcanza un tamaño determinado, el diseño cambia para ajustarse. Es una opción válida si el presupuesto es limitado, pero su nivel de usabilidad es bajo y la experiencia en dispositivos móviles puede verse reducida. 

## 3. **Diseño Web Responsivo (RWD - Responsive Web Design)** 

El diseño responsivo adapta tanto el contenido como la presentación a diferentes tamaños de pantalla. Utiliza **media queries** de CSS3 para ajustar la visualización en función de la resolución de la pantalla, asegurando una experiencia de usuario similar en dispositivos de diferentes tamaños. A diferencia del diseño adaptativo, el diseño responsivo tiene un solo diseño que se ajusta automáticamente, usando tamaños proporcionales y medidas en porcentajes, lo que lo hace más flexible, aunque puede requerir mayor tiempo de carga. 

## **Comparativa entre Diseño Web Adaptativo y Responsivo** : 

- Adaptive Web Design (AWD): 

   - 1. Tamaños de pantalla fijos y preestablecidos. 

   - 2. Valores fijos en píxeles. 

   - 3. Menor tiempo de carga. 

   - 4. Reestructura elementos para optimizar espacio y experiencia de usuario. 

   - 5. Menos flexibilidad. 

- Responsive Web Design (RWD): 

   - 1. Adaptable a cualquier pantalla. 

   - 2. Utiliza tamaños proporcionales (porcentajes). 

   - 3. Emplea media quieres y diferentes estilos por pantalla. 

   - 4. Alta flexibilidad. 

   - 5. Puede tener mayor tiempo de carga. 

## **<u>Ejemplos prácticos de implementación de WCAG</u>** 

- **Texto alternativo en imágenes (Pauta 1.1.1)** : Asegúrate de que todas las imágenes de un sitio web tienen texto alternativo (atributo alt Esto permite a las personas con discapacidad visual entender el contenido de la imagen a través de lectores de pantalla. 

- **Subtítulos en contenido multimedia (Pauta 1.2.2)** : En videos, incluir subtítulos es fundamental para garantizar que las personas con discapacidad auditiva puedan acceder a la información 

- **Contraste adecuado (Pauta 1.4.3)** : Asegúrate de que haya suficiente contraste entre el texto y el fondo para facilitar la lectura. Un ejemplo práctico sería verificar que el texto en una página web con fondo oscuro tenga un contraste suficiente con el color del texto para que las personas con baja visión puedan leerlo cómodamente. 

- **Navegación mediante teclado (Pauta 2.1.1)** : Asegúrate de que todo el contenido y las funcionalidades sean accesibles mediante teclado. Esto significa que los usuarios no necesiten un mouse para navegar por el sitio. 

## **<u>Herramientas para evaluar la accesibilidad web</u>** 

- **WAVE (Web Accessibility Evaluación Tool)** : Es una herramienta gratuita que analiza la accesibilidad de un sitio web y proporciona un informe visual de los errores encontrados. Se destaca por su facilidad de uso y su capacidad para señalar problemas relacionados con las WCAG. 

- **AXE Accessibility Testing** : Es una extensión de navegador (para Chrome y Firefox) que permite realizar pruebas de accesibilidad en tiempo real mientras navegas por un sitio web. Ayuda a detectar problemas relacionados con las pautas WCAG y puede integrarse con sistemas de pruebas automatizadas. 

- **Lighthouse (de Google)** : Lighthouse es una herramienta automatizada de Google que realiza auditorías sobre accesibilidad, rendimiento y mejores prácticas en un sitio web. Proporciona un informe detallado con puntuaciones y sugerencias sobre cómo mejorar la accesibilidad. 

- **Color Contrast Analyzer** : Es una herramienta que ayuda a evaluar si el contraste de color entre el texto y el fondo de una página cumple con los requisitos de las WCAG 2.1, especialmente en relación con el contraste necesario para personas con baja visión.

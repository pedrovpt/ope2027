# **1. Introducción** 

Un **sistema operativo (SO)** es el software fundamental que gestiona los recursos del hardware y software de un dispositivo, permitiendo la interacción entre el usuario y el equipo. Su objetivo principal es proporcionar un entorno estable y eficiente para la ejecución de programas y el control de los recursos del sistema. 

# **1.1. Conceptos básicos: núcleo, firmware e interrupciones** 

- **Núcleo (kernel)** : parte central del SO que se ejecuta en **modo núcleo o supervisor** (privilegiado) y tiene acceso completo al hardware. Las aplicaciones se ejecutan en **modo usuario** y solicitan servicios al kernel mediante **llamadas al sistema (system calls)** . 

- **Firmware** : **soporte lógico inalterable** (o difícilmente modificable) grabado en una memoria no volátil (ROM, EEPROM, flash) que **controla los circuitos electrónicos de un dispositivo** a bajo nivel. Ejemplos: BIOS/UEFI de la placa base, firmware de un disco, de una impresora o de un router. Se sitúa entre el hardware y el software. 

- **BIOS / UEFI** : firmware de arranque del PC. Realiza el **POST** (autodiagnóstico), inicializa el hardware y cede el control al cargador de arranque (bootloader). **UEFI** es la evolución de la BIOS: admite discos GPT de más de 2 TB, interfaz gráfica y **arranque seguro (Secure Boot)** , que solo permite cargar software firmado. 

- **Interrupción (IRQ, Interrupt ReQuest)** : **aviso (señal) generado por un dispositivo hardware para requerir la atención de la CPU** . La CPU suspende lo que está haciendo, guarda el contexto y ejecuta la **rutina de servicio de interrupción (ISR)** del driver correspondiente. Evita el **sondeo (polling)** , en el que el SO pregunta periódicamente a los dispositivos si necesitan algo. 

   - **Tipos de interrupciones** : hardware (dispositivos: teclado, disco, tarjeta de red, reloj), software o **traps** (llamadas al sistema) y **excepciones** (errores: división por cero, fallo de página, acceso a memoria no permitido). 

- **DMA (Direct Memory Access)** : permite a un dispositivo transferir datos directamente a memoria sin intervención de la CPU, que solo recibe una interrupción al terminar.

# **2. Funciones principales de un sistema operativo** 

Un **sistema operativo (SO)** es el software que actúa como **intermediario entre el hardware y el usuario** . Su función principal es **gestionar los recursos del sistema** y **proporcionar servicios a los programas y usuarios,** realizando principalmente las siguientes funciones: 

# **2.1. Gestión de procesos** 

- Controla la **creación, planificación, ejecución, suspensión y terminación** de procesos. 

- Asigna **tiempo de CPU** según criterios (prioridad, planificación…). 

- Coordina la **sincronización y comunicación entre procesos** (IPC). 

- Utiliza técnicas como **multitarea** , **multiprogramación** o **hilos (threads)** . 

_Ejemplo: El comando top en Linux o el "Administrador de tareas" en Windows._ 

# **Concepto de proceso** 

Un **programa** es una entidad pasiva (fichero ejecutable almacenado en disco). Un **proceso** es un **programa en ejecución** : entidad activa con su código, datos, pila, registros, contador de programa y recursos asignados. En un sistema operativo moderno, 

**el proceso es la unidad de trabajo fundamental** (la unidad de asignación de recursos). El **hilo (thread)** es la unidad mínima de ejecución (planificación) dentro de un proceso; los hilos de un mismo proceso comparten memoria y recursos. 

- **Estados de un proceso** : nuevo → **listo** → **en ejecución** → **bloqueado/en espera** (por E/S o evento) → terminado. El paso de ejecución a listo se produce por expropiación (fin del quantum o llegada de un proceso más prioritario). 

- **PCB (Process Control Block, bloque de control de proceso)** : estructura donde el SO guarda la información de cada proceso (PID, estado, registros, prioridad, memoria asignada, ficheros abiertos…). 

- **Cambio de contexto** : operación del kernel que guarda el estado del proceso saliente en su PCB y carga el del entrante. 

# **Planificación de la CPU (scheduling)** 

El **planificador** decide qué proceso del estado listo pasa a usar la CPU. Puede ser **no expropiativo** (el proceso retiene la CPU hasta que termina o se bloquea) o **expropiativo** (el SO puede retirarle la CPU). Criterios: uso de CPU, productividad (throughput), tiempo de retorno, tiempo de espera y tiempo de respuesta.

En un **UNIX de tiempo compartido** con un único procesador, en condiciones normales el siguiente proceso en usar la CPU se elige según **la prioridad del proceso** (prioridad dinámica, que el kernel recalcula en función del uso reciente de CPU y del valor **nice** ). El **quantum** determina cuánto tiempo se ejecuta, no quién se ejecuta. En Linux el planificador por defecto ha sido el **CFS** (Completely Fair Scheduler), sustituido desde el kernel 6.6 por **EEVDF** . 

# **Interbloqueos (deadlocks)** 

Un **interbloqueo** es una situación en la que un conjunto de procesos queda bloqueado permanentemente porque cada uno espera un recurso retenido por otro del mismo conjunto. Se produce solo si se cumplen simultáneamente las **cuatro condiciones de Coffman** : 

- **Exclusión mutua** : el recurso solo puede usarlo un proceso a la vez. 

- **Retención y espera** : un proceso retiene recursos mientras espera otros. 

- **No expropiación** : los recursos no se pueden quitar a la fuerza. 

- **Espera circular** : existe una cadena circular de procesos que se esperan mutuamente. 

# **Estrategias para manejar los interbloqueos:** 

|**Estrategia**|**Descripción**|
|---|---|
|**Prevención**|Diseñar el sistema para que nunca se cumpla alguna de las<br>cuatro condiciones (p. ej., pedir todos los recursos a la vez u<br>ordenar los recursos numéricamente).|
|**Evitación**|Antes de conceder un recurso se comprueba que el sistema<br>queda en un**estado seguro**. El algoritmo clásico es el<br>**algoritmo del banquero**(Dijkstra): cada proceso declara sus<br>necesidades máximas y solo se conceden peticiones que<br>mantengan el estado seguro.|
|**Detección y**<br>**recuperación**|Se permite que ocurran; el SO los detecta (grafo de asignación<br>de recursos) y se recupera terminando procesos o expropiando<br>recursos (rollback).|
|**Ignorarlos**<br>**(algoritmo del**<br>**avestruz)**|Se asume que son raros y no se hace nada. Es lo que hacen en<br>la práctica Windows y la mayoría de UNIX/Linux.|



_Técnicas como el “incremento aleatorio de la prioridad de los procesos” o la asignación FIFO/cíclica de recursos NO son estrategias de manejo de interbloqueos._ 

# **2.2. Gestión de la memoria** 

- Controla el uso de la **memoria principal (RAM)** . 

- 

   - Asigna y libera memoria a procesos. 

- 

   - Implementa técnicas como: 

      - **Memoria virtual** 

      - **Paginación** (en bloques fijos). 

      - **Segmentación** 

      - **Swapping** (intercambio entre RAM y disco). 

- Asegura que los procesos no interfieran entre sí (protección de memoria), evitando errores y conflictos. 

# **Contabilización de la memoria libre** 

El SO necesita saber qué partes de la memoria están libres u ocupadas. Los dos métodos clásicos para **contabilizar la utilización de memoria** son: 

- **Mapas de bits** : la memoria se divide en unidades de asignación y cada una se representa con un bit (0 libre, 1 ocupada). 

- **Listas enlazadas** : se mantiene una lista enlazada de segmentos de memoria asignados y libres (huecos). Algoritmos de ubicación: primer ajuste (first fit), siguiente ajuste, mejor ajuste (best fit) y peor ajuste (worst fit). 

_No confundir con los algoritmos de sustitución de páginas (FIFO, NRU, LRU…) ni con las tablas de páginas, que sirven para otras funciones._ 

# **Paginación, MMU y TLB** 

- **Paginación** : la memoria lógica del proceso se divide en **páginas** de tamaño fijo y la física en **marcos** del mismo tamaño. Permite asignar a un proceso **marcos físicos no contiguos** mientras el proceso ve un **espacio de direcciones lógicas continuo** . Elimina la fragmentación externa, aunque puede haber fragmentación interna en la última página. 

- **MMU (Memory Management Unit)** : componente hardware que traduce en tiempo de ejecución las direcciones lógicas (virtuales) a físicas usando la **tabla de páginas** . La **memoria virtual con MMU** es la técnica que, combinada con la paginación, ofrece a cada proceso un espacio lógico continuo. 

- **TLB (Translation Lookaside Buffer)** : pequeña caché asociativa dentro de la MMU que guarda las traducciones más recientes para acelerar el acceso; no es una técnica de asignación. 

- **Tablas de páginas multinivel** : la tabla de páginas se divide jerárquicamente (2, 3, 4 o 5 niveles en x86-64) para no tener en memoria entradas de zonas no usadas del espacio de direcciones. 

- **Memoria virtual y paginación por demanda (demand paging)** : las páginas solo se cargan en RAM cuando se necesitan. Si se accede a una página no cargada se produce un **fallo de página** y el SO la trae desde el disco ( **archivo de paginación** pagefile.sys en Windows, **área swap** en Linux). Permite que un proceso **use más memoria de la físicamente disponible** . 

- **Swapping** : intercambio de procesos completos entre la RAM y el disco. 

# **Segmentación** 

- Divide la memoria del proceso en **segmentos de tamaño variable** que corresponden a unidades lógicas del programa (código, datos, pila…). Cada dirección es un par (segmento, desplazamiento). 

- Facilita la protección y la **compartición** de código y datos entre procesos, pero **produce fragmentación externa** (no la elimina). Muchos sistemas combinan **segmentación paginada** . 

# **Algoritmos de sustitución de páginas** 

Cuando se produce un fallo de página y no hay marcos libres, el SO elige una página víctima: 

- **Óptimo (OPT)** : sustituye la página que tardará más en usarse. Teórico, sirve de referencia. 

- **FIFO** : sustituye la página más antigua. Puede sufrir la **anomalía de Belady** (más marcos, más fallos). 

- **NRU (No usada recientemente)** : clasifica las páginas según los bits de referencia (R) y modificación (M). 

- **LRU (Least Recently Used)** : sustituye la página que lleva más tiempo sin usarse. 

- **Segunda oportunidad y reloj (clock)** : variantes eficientes de FIFO que usan el bit de referencia. 

Si el sistema pasa más tiempo paginando que ejecutando se produce **hiperpaginación (thrashing)** . 

# **Protección de memoria y “segmentation fault”** 

En un SO multiusuario cada proceso tiene su propio espacio de direcciones y solo el núcleo (o procesos con privilegios especiales) puede acceder a la memoria de otros procesos. Un **“segmentation fault”** (violación de segmento; en Windows, *access violation*) es el mensaje del SO al **terminar un proceso que intenta acceder a una zona de memoria restringida** o no asignada (por ejemplo, desreferenciar un puntero nulo o salirse de un array). El SO envía la señal **SIGSEGV** y finaliza el proceso para proteger al resto del sistema. 

# **Límites de direccionamiento: 32 y 64 bits** 

- Un SO de **32 bits** puede direccionar como máximo **2³² bytes = 4 GB** de memoria. Por ejemplo, **Windows 7 de 32 bits admite un máximo de 4 GB** (y en la práctica suele mostrar unos 3–3,5 GB utilizables, porque parte del espacio se reserva para dispositivos). La extensión **PAE** permite más memoria física en ediciones de servidor, pero no en las versiones cliente de Windows. 

- Un SO de **64 bits** admite muchísimo más (Windows 7 Home Premium x64: 16 GB; Professional/Enterprise/Ultimate x64: 192 GB; Windows 10/11 Pro x64: hasta 2 TB).

# **2.3. Gestión del sistema de archivos y almacenamiento** 

- Administra la **creación, lectura, escritura y borrado** de archivos y directorios en discos duros, SSD y otros medios de almacenamiento. 

- Proporciona estructuras de almacenamiento organizadas (como árboles de directorios). 

- Controla el acceso a archivos mediante **permisos** y **propiedades** . 

- Soporta múltiples sistemas de archivos: **FAT, NTFS, ext4** , etc. 

_Ejemplo: comando df o mount en Linux._ 

# **Bloques (clústeres): tamaño vs. tamaño en disco** 

Los sistemas de archivos asignan espacio en **bloques o clústeres** de tamaño fijo (por ejemplo, 4 KB en NTFS o ext4). Un archivo ocupa siempre un número entero de clústeres, por lo que el último queda parcialmente vacío ( **fragmentación interna** o “slack”). Por eso, al consultar las propiedades de una carpeta en Windows aparecen dos valores: **“Tamaño”** (suma de los tamaños reales de los ficheros) y **“Tamaño en disco”** (espacio realmente reservado). **El tamaño de los archivos puede ser menor que el tamaño en disco que ocupan, debido al ajuste de bloque** (también puede ser mayor si están comprimidos o son ficheros dispersos). En Linux: **du** (tamaño en disco) frente a **ls -l** o **du - -apparent-size** .

# **Journaling y enlaces** 

- **Journaling** : el sistema de archivos registra en un diario (journal) las operaciones antes de realizarlas, para recuperar la coherencia rápidamente tras un apagado brusco (NTFS, ext3/ext4, XFS). 

- **Enlace duro (hard link)** : nueva entrada de directorio que apunta al **mismo inodo** que el archivo original. Permite que **un único archivo aparezca en varios directorios a la vez sin duplicar su contenido en disco** . El archivo solo se borra cuando se elimina el último enlace. No puede cruzar sistemas de archivos ni (normalmente) apuntar a directorios. Linux: **ln origen enlace** ; Windows (NTFS): **mklink /H** . 

- **Enlace simbólico (soft link)** : fichero especial que contiene la ruta de otro. Puede apuntar a directorios y a otros sistemas de archivos, pero queda “roto” si se borra el original. Linux: **ln -s** ; Windows: **mklink** / **mklink /D** . Los **accesos directos** (.lnk) de Windows son ficheros del shell, no enlaces del sistema de archivos. 

# **Permisos en Linux/UNIX** 

Cada fichero tiene un **propietario (u)** , un **grupo (g)** y el resto de usuarios, **otros (o)** . Para cada uno se definen tres permisos: **r** (lectura, valor 4), **w** (escritura, valor 2) y **x** (ejecución, valor 1). El listado **ls -l** los muestra en 10 caracteres: tipo de fichero (- fichero, d directorio, l enlace) seguido de tres tríos rwx para usuario, grupo y otros.

# **2.5. Gestión de usuarios y seguridad**

- Proporciona aislamiento entre usuarios y procesos. 

- Administra **grupos, privilegios** (lectura, escritura, ejecución) y **protección de datos** . 

- Autenticación (usuario/contraseña, certificados…). 

- En sistemas multiusuario (Linux, Windows Server), distingue entre: 

   - Usuarios normales 

   - Administradores/root 

_Ejemplo: Comando chmod o sudo en Linux; “Usuarios y grupos” en Windows._ 

# **Tipos de cuentas de usuario en Windows** 

- **Administrador** : control total del equipo (instalar software, cambiar configuración, gestionar otras cuentas). 

- **Usuario estándar** : puede usar la mayoría del software y cambiar ajustes que no afectan a otros usuarios ni a la seguridad. **Es la cuenta recomendada para el trabajo diario** , también en equipos compartidos. 

- **Invitado** : acceso temporal muy limitado; viene deshabilitada por defecto y en Windows 10/11 ya no se puede usar como tal. 

- Según su origen, las cuentas pueden ser **locales** , **de dominio** (Active Directory) o **cuentas Microsoft / Microsoft Entra ID** (antes Azure AD). 

# **Control de cuentas de usuario (UAC)** 

Introducido por Microsoft en **Windows Vista** (2007) tras numerosas escaladas de privilegios, el **Control de cuentas de usuario (UAC, User Account Control)** hace que incluso los administradores trabajen por defecto con privilegios de usuario estándar. Cuando una tarea requiere privilegios elevados (instalar software, cambiar configuración del sistema) se muestra un aviso en el **escritorio seguro** que pide confirmación o credenciales de administrador ( **elevación de privilegios** ). 

**Otras medidas de seguridad en Windows** 

- **Windows + L** : bloquea el equipo al instante; buena práctica al ausentarse del puesto. 

- **BitLocker** : herramienta de Windows (ediciones Pro, Enterprise y Education; desde Windows Vista) para **cifrar unidades o volúmenes completos** , apoyándose en el chip **TPM** . **BitLocker To Go** cifra unidades extraíbles. En Windows 11 Home existe una versión reducida llamada “Cifrado de dispositivo”. 

- **Microsoft Defender** (antivirus), **Firewall de Windows Defender** , **Windows Hello** (biometría/PIN) y **SmartScreen** .

   - Ofrece **interfaces de comunicación** : 

      - Línea de comandos (CLI) → bash, cmd 

      - Interfaces gráficas (GUI) → Windows, GNOME, macOS 

   - Permite ejecutar y gestionar aplicaciones fácilmente. 

- **2.8. Mantenimiento, recuperación y tolerancia a fallos** 

   - Gestiona errores y proporciona mecanismos de **respaldo** (backup), **restauración** y **recuperación** . 

   - Implementa **actualizaciones, parches** y monitorización para prevenir fallos. 

- **2.9. Actualización y evolución** 

   - Permite incorporar nuevas funcionalidades, corregir errores o adaptarse a nuevos dispositivos mediante **actualizaciones del sistema** . 

- **2.10. Gestión de la seguridad del sistema** 

   - Control de acceso a archivos, dispositivos y funciones del sistema. 

   - Instalación de **actualizaciones de seguridad** y **parches** . 

   - Configuración de: 

      - **Cortafuegos (firewall)** 

      - **Antivirus / antispyware** 

      - **Auditoría de eventos** 

   - Mecanismos de respaldo y recuperación. 

- **2.11. Configuración y mantenimiento** 

   - Configuración del entorno del sistema: 

      - Red, hardware, servicios, arranque... 

   - Mantenimiento preventivo: 

      - Limpieza de archivos temporales 

      - Desfragmentación (en sistemas con HDD) 

      - Monitoreo del uso de CPU, RAM, disco y red 

   - Restauración y recuperación ante errores. 

_Herramientas: msconfig, “Liberador de espacio en disco”, “Restaurar sistema” (Windows); cron, systemctl, journalctl (Linux)._ 

# **2.12. Gestión del sistema en red** 

- Compartición de archivos y dispositivos (impresoras, discos). 

- Administración remota (SSH, escritorio remoto). 

- Configuración de IP, DNS, puerta de enlace, DHCP, etc. 

- Servicios de red: servidores web, FTP, correo, etc.

# **3. Evolución de los sistemas operativos** 

La evolución de los sistemas operativos ha ido de la mano del avance del hardware y las necesidades de los usuarios. Se suele dividir en **generaciones tecnológicas** , cada una marcada por avances clave: 

**Prehistoria (Siglo XIX – 1940s). Generación Cero.** 

- No existían sistemas operativos. Las máquinas se diseñaban, construían, programaban y mantenían por un grupo reducido de gente. 

- Charles Babbage diseñó la _máquina analítica_ (no se llegó a construir). 

   - Ada Lovelace escribió el **primer algoritmo** (considerada la primera programadora). 

   - Las máquinas se programaban mediante **tarjetas perforadas** . 

- **1ª Generación (1945–1955) – Tubos de vacío** 

   - Computadoras como ENIAC, Z3, Colossus. 

   - No tenían SO, se programaban manualmente. 

   - Lenguaje máquina y configuración por hardware. 

   - Alta dependencia del operador humano. 

_No existía multitarea ni almacenamiento secundario como lo conocemos hoy._ 

# **2ª Generación (1955–1965) – Transistores y sistemas batch** 

- Introducción de **sistemas batch (por lotes)** . 

- Aparecen los primeros lenguajes de alto nivel (FORTRAN). 

- Surge el concepto de **monitor de sistema** para ejecutar trabajos automáticamente. 

- Introducción de lectores de tarjetas, impresoras y cintas magnéticas. 

_Empiezan a aparecer los primeros "proto-sistemas operativos" como IBSYS, FMS. Monousuario y monotarea._ 

- **3ª Generación (1965–1980) – Circuitos integrados y multiprogramación** 

   - Nace el concepto de **multiprogramación** y **spooling** . 

   - IBM lanza su familia de computadoras **System/360** con el SO **OS/360** . 

   - Aparecen **sistemas de tiempo compartido (timesharing)** como CTSS. 

   - Desarrollo de **UNIX** (Ken Thompson y Dennis Ritchie). **Multiusuario** . 

   - Se implementan los primeros **mecanismos de protección de memoria y multitarea** . 

_La informática comienza a ser interactiva, no solo por lotes._ 

- **4ª Generación (1980–Presente) – Computadoras personales** 

   - Aparición de los **microprocesadores (Intel 8080, 8086)** . 

   - Explosión de los **microordenadores y PCs** : Apple II, IBM PC. 

- Popularización de **MS-DOS** , luego **Windows** , **Mac OS** y distribuciones **Linux** . 

- Las interfaces gráficas (GUI) se generalizan (influencia de Xerox PARC, Apple Macintosh). 

- **Sistemas operativos modernos** combinan multitarea, multiproceso, GUI, red, multimedia... 

_Aumenta la accesibilidad, nace la informática doméstica y de oficina._ 

**5ª Generación (1990–Presente) – Dispositivos móviles y conectividad** 

- Aparición de **smartphones y tablets** . 

- Desarrollo de sistemas como **Symbian** , **Palm OS** , **Windows Mobile** , luego **Android** e **iOS** . 

- Los sistemas operativos móviles requieren: 

   - Bajo consumo 

   - Alta conectividad (WiFi, Bluetooth) 

   - Interfaz táctil y sensores 

_Se prioriza la eficiencia energética, la conectividad y la interacción táctil._

# **5. Administración y gestión del sistema operativo** 

La administración de un SO implica diversas tareas para garantizar su correcto funcionamiento: (mirar punto 2 del presente tema) 

- **Monitorización del rendimiento** → Supervisión de CPU, memoria y procesos activos. **Gestión de usuarios y permisos** → Configuración de cuentas, accesos y privilegios. **Instalación de actualizaciones** → Aplicación de parches de seguridad y mejoras de 

- software. 

- **Configuración de hardware y software** → Instalación de drivers, configuración de red 

- y optimización de recursos. 

# **5.1. Gestión de parches y actualizaciones de seguridad** 

Antiguamente los sistemas de control de procesos se basaban en tecnologías propietarias o aisladas y el parcheo no se consideraba prioritario. Hoy, en entornos interconectados como la **Red Corporativa de la Junta de Andalucía** y el **SAS** , el parcheo es una tarea continua y crítica: 

- **La existencia de cortafuegos perimetrales no exime de actualizar los equipos** : se aplica el principio de **defensa en profundidad** (varias capas de protección), ya que las amenazas pueden venir del interior de la red, de equipos portátiles o de correo/web. 

- **Un sistema correctamente parcheado está protegido en gran medida** frente a intrusiones que explotan vulnerabilidades conocidas. 

- **La aplicación de parches no está libre de riesgos** : un parche puede causar un funcionamiento incorrecto del sistema o de aplicaciones críticas. Por eso se prueban antes en un **entorno de preproducción o grupo piloto** , se programan en ventanas de mantenimiento, se hace copia de seguridad previa y se prevé **marcha atrás (rollback)** . 

- Herramientas de despliegue: **WSUS** , **Microsoft Configuration Manager (SCCM/MECM)** , **Intune** ; en Linux, repositorios propios con apt/dnf y herramientas como Ansible. Referencias normativas: **Esquema Nacional de Seguridad (ENS, RD 311/2022)** y guías **CCN-STIC** . 

# **5.2. Configuración de red en clientes Windows** 

- **IPv4 e IPv6** conviven (pila dual). IPv4 no está obsoleto ni en desuso, e **IPv6 se puede desactivar** en las propiedades del adaptador (aunque Microsoft no lo recomienda). 

- **DHCP** : el cliente obtiene automáticamente IP, máscara, puerta de enlace y DNS. 

- **APIPA (Automatic Private IP Addressing)** : si el cliente está configurado por DHCP y **no encuentra servidor DHCP** , se autoasigna una IP del rango **169.254.0.0/16** 

(máscara 255.255.0.0). Solo permite comunicarse con equipos del mismo segmento que también usen APIPA; no tiene salida a otras redes. 

- En configuración manual, **la puerta de enlace y los servidores DNS son opcionales** : se puede guardar la configuración solo con IP y máscara (el equipo funcionará en la red local). 

- **Prioridad cable/Wi-Fi** : Windows usa la **métrica de interfaz** (automática, según velocidad); normalmente **la red cableada tiene prioridad** sobre la Wi-Fi, y la métrica puede modificarse manualmente. 

- Comandos útiles: **ipconfig /all** , **ipconfig /release** y **/renew** , **ipconfig /flushdns** , **ping** , **tracert** , **nslookup** , **netsh** , **Get-NetIPConfiguration** (PowerShell). 

# **5.3. Administración centralizada: Active Directory** 

**Active Directory (AD)** es el servicio de directorio de Microsoft que almacena de forma jerárquica la información de los objetos de la red (usuarios, grupos, equipos, impresoras, carpetas compartidas) y permite la **autenticación y autorización centralizadas** (Kerberos) y la aplicación de políticas. 

- **AD DS (Active Directory Domain Services)** : **rol de Windows Server** fundamental para gestionar usuarios, grupos y políticas de seguridad centralizadas. Otros roles: DNS, DHCP, IIS, Hyper-V, AD CS (certificados)… 

- **Controlador de dominio (DC)** : servidor con el rol AD DS que **almacena y gestiona la base de datos de Active Directory** (NTDS.dit) y proporciona autenticación y autorización a usuarios y equipos del dominio. Se recomienda tener **al menos dos DC** para redundancia; se replican entre sí (replicación multimaestro). 

- **Promoción a controlador de dominio** : tradicionalmente con el comando **dcpromo** (Windows 2000 a Windows Server 2008 R2). Desde Windows Server 2012, dcpromo está obsoleto y la promoción se hace desde el **Administrador del servidor (Server Manager)** tras instalar el rol AD DS, o con PowerShell ( **InstallADDSDomainController** , **Install-ADDSForest** ). 

- **LDAP (Lightweight Directory Access Protocol)** : **protocolo estándar para leer o modificar la información del directorio** (puerto 389; LDAPS 636; catálogo global 3268). Las aplicaciones que consultan o modifican AD sin conocer su estructura interna usan LDAP o interfaces como **ADSI** . 

- **Estructura lógica** : **bosque** → **árbol** → **dominio** → **unidades organizativas (OU)** → objetos. Estructura física: **sitios** y controladores de dominio. 

# **Nombres de objetos en AD** 

- **Distinguished Name (DN)** : nombre completo y único del objeto, con toda su ruta en el directorio, desde el objeto hasta la raíz. Ejemplo: **CN=ANDALUZ ANDALUZ JUAN,OU=Enfermeros,DC=ephpo,DC=hos** (es el DN completo). 

- **Relative Distinguished Name (RDN)** : la parte que identifica al objeto dentro de su contenedor, p. ej. **CN=ANDALUZ ANDALUZ JUAN** . 

- Atributos: **CN** (Common Name), **OU** (Organizational Unit), **DC** (Domain Component). Formato canónico: ephpo.hos/Enfermeros/ANDALUZ ANDALUZ JUAN. El dominio en formato DNS sería ephpo.hos. 

# **Unidades organizativas (OU)** 

- Contenedores que **pueden contener usuarios, grupos, equipos y otras OU** (anidamiento). 

- Se les pueden **vincular directivas de grupo (GPO)** y **delegar la administración** . 

- Sirven para **representar la estructura jerárquica lógica de la organización** (departamentos, centros, categorías…). 

- **Una OU no puede contener objetos de otros dominios** : su ámbito es siempre el dominio en el que se crea.

# **5.4. Unión de equipos a un dominio (caso del dominio corporativo DMSAS)** 

**Unión de un equipo Windows 7/10 a un dominio** : botón derecho en **Equipo / Este equipo → Propiedades** (equivale a **Panel de control → Sistema y seguridad → Sistema** ) → **Configuración avanzada del sistema / Cambiar configuración** → pestaña **Nombre de equipo** → **Cambiar…** → marcar **Dominio** , escribir el nombre, introducir credenciales con permiso para unir equipos y reiniciar. Atajo: **sysdm.cpl** . En Windows 10/11 también desde **Configuración → Cuentas → Obtener acceso a trabajo o escuela** , o con PowerShell **AddComputer -DomainName** . 

_En la vista por categorías de Windows 7 no existe “Panel de control → Sistema” de primer nivel (está dentro de “Sistema y seguridad”), ni la unión se realiza desde “Aplicaciones” o “Cuentas de usuario”._ 

**DMSAS** es el dominio corporativo único de Active Directory del Servicio Andaluz de Salud. Requisitos previos habituales para migrar un puesto al dominio DMSAS: 

- Verificar la disponibilidad de la cuenta de administración **ADM_** del técnico en DMSAS, ya que con ella se realizan todas las operaciones sobre los PC a migrar (tiene derechos de administrador). 

- **Se recomienda almacenar la información laboral en los recursos de red** puestos a disposición del usuario (carpetas privadas y carpetas de grupo). **No es obligatorio** (ni recomendable) guardar toda la información del usuario en el disco local del PC. 

- Elaborar un **listado de las aplicaciones** que el equipo tenga de forma excepcional, para probarlas tras la migración o reinstalarlas si fuera necesario. 

- Hacer copia de seguridad del perfil y de los datos locales antes de la migración. 

# **6. Planes de implantación y migración** 

La **implantación** y **migración** de un sistema operativo (SO) son procesos planificados que permiten sustituir, actualizar o instalar un nuevo sistema en una organización o equipo informático, minimizando riesgos y garantizando la continuidad operativa. 

# **1. Plan de Implantación de un Sistema Operativo** 

Es el conjunto de acciones necesarias para **instalar, configurar y poner en marcha** un sistema operativo en un entorno concreto. Se divide en **fases** : 

# **Fase 1: Consultoría y análisis** 

- Identificación de **necesidades del usuario o empresa** . 

- Evaluación del sistema actual (hardware, software, problemas, limitaciones). 

- Determinación de los **objetivos del nuevo sistema** : rendimiento, seguridad, compatibilidad... 

- Análisis de costes y beneficios. 

_Resultado: Documento de requisitos y estudio de viabilidad._ 

# **Fase 2: Gestión del proyecto** 

- Selección del sistema operativo más adecuado. 

- Planificación de tareas, cronograma, recursos humanos y técnicos. 

- Presupuesto detallado (licencias, hardware, soporte...). 

- Asignación de responsabilidades (quién hace qué). 

_Aquí se diseñan pruebas piloto o entornos de ensayo (sandbox)._ 

# **Fase 3: Implantación técnica** 

- Instalación del nuevo SO. 

- Configuración de servicios, usuarios, red, impresoras... 

- Migración de datos si es necesario. 

- Pruebas de funcionalidad. 

_Puede hacerse de forma centralizada, remota o máquina por máquina._ 

# **Fase 4: Formación de usuarios** 

- Capacitación para personal técnico y usuarios finales. 

- Manuales de uso, guías, formación presencial o virtual. 

- Soporte inicial para resolver dudas y errores. 

# **Fase 5: Soporte y mantenimiento** 

- Monitorización del nuevo sistema. 

- Atención de incidencias y errores. 

- Mantenimiento preventivo y correctivo. 

- Actualizaciones y parches de seguridad. 

_Incluye contratos de soporte, copias de seguridad y documentación._ 

# **2. Plan de Migración de un Sistema Operativo** 

La **migración** implica pasar de un sistema operativo a otro (ej. de Windows 7 a Windows 11, o de Windows a Linux), conservando datos y funcionalidades. 

# **¿Por qué migrar?** 

- Fin del soporte del SO actual (ej. Windows 7). 

- Necesidad de nuevas funciones, mayor seguridad o compatibilidad. 

- Reducción de costes (migrar a software libre). 

- Estándares corporativos. 

# **Fases de un plan de migración** 

# **1. Estudio de viabilidad** 

- Análisis técnico: ¿es compatible el nuevo sistema con el hardware actual? 

- Análisis económico: ¿es viable el coste? 

- Evaluación de riesgos y plan de contingencia. 

# **2. Análisis y diseño del sistema** 

- Determinación de requisitos exactos del nuevo SO. 

- Elección del tipo de instalación (dual boot, virtualización, migración total...). 

- Definición de interfaces, servicios y estructura de usuarios. 

- Plan de pruebas. 

# **3. Desarrollo y preparación** 

- Preparación de imágenes del sistema. 

- Copias de seguridad completas. 

- Herramientas de migración (p. ej., USMT para Windows, Clonezilla, scripts personalizados). 

# **4. Implantación y validación** 

- Ejecución de la migración en fases (piloto, por departamentos...). 

- Comprobación de compatibilidad con el software existente. 

- Validación de que todo funciona correctamente. 

# **5. Formación y documentación** 

- Formación técnica y operativa. 

- Manuales y fichas de ayuda. 

- Soporte de transición. 

# **6. Mantenimiento post-migración** 

- Atención a errores o problemas. 

- Revisión periódica del funcionamiento. 

- Optimización progresiva. 

|**Fase**|**Descripción**|
|---|---|
|**Consultoría y análisis**|Evaluar necesidades y entorno actual.|
|**Diseño del proyecto**|Elegir SO, definir recursos, elaborar cronograma y<br>presupuesto.|
|**Instalación / Migración**|Instalación técnica, transferencia de datos, configuración.|
|**Formación**|Capacitar usuarios y personal técnico.|
|**Validación y pruebas**|Asegurar que el sistema cumple los requisitos.|
|**Soporte y**<br>**mantenimiento**|Resolución de incidencias, actualizaciones, copias de<br>seguridad.|



# **Buenas prácticas** 

- Hacer **copias de seguridad previas** . 

- Ejecutar pruebas piloto antes de implantar en toda la organización. 

- Documentar todos los pasos del proceso. 

- Establecer canales de soporte durante y después de la implantación. 

- Minimizar el tiempo de inactividad (uso de horarios valle, despliegues 

- progresivos). 

# **7. Instalación, configuración y optimización del sistema operativo** 

El proceso de instalación de un sistema operativo sigue los siguientes pasos básicos: 

# **7.1. Instalación del sistema operativo** 

Consiste en **preparar e implantar el SO en el equipo** para su funcionamiento inicial. Puede ser una instalación desde cero o una reinstalación/migración. 

# **Requisitos previos:** 

- Soporte de instalación (USB, CD, imagen ISO). 

- Compatibilidad del hardware (CPU, RAM, espacio en disco).

- **Monitor de rendimiento (perfmon)** : contadores de rendimiento, recopiladores de datos e informes a largo plazo.

# **9. Sistemas operativos en dispositivos móviles** 

Un **sistema operativo móvil** es un software que gestiona el hardware de un **dispositivo portátil** (como smartphones, tablets, relojes inteligentes, etc.) y proporciona una **interfaz al usuario y a las aplicaciones** . Los SO móviles están diseñados para optimizar el consumo de batería y garantizar estabilidad en smartphones y tablets. 

# **Características clave de un SO móvil** 

- Interfaz **táctil e intuitiva** . 

- Uso eficiente de **batería y recursos** . 

- Soporte de **sensores** (giroscopio, GPS, proximidad…). 

- **Conectividad constante** (WiFi, Bluetooth, 4G/5G). 

- Ecosistema de **aplicaciones móviles** (App Stores). 

- Seguridad avanzada: **sandboxing** , permisos, cifrado. 

**Evolución histórica de los sistemas operativos móviles** 

**Años 90 – Inicios: PDAs y primeros móviles "inteligentes"** 

- **Palm OS** : pionero en asistentes personales digitales (PalmPilot). 

- **Symbian OS** (Nokia): multitarea, interfaz gráfica, muy popular en la década de 2000. 

- **Windows CE / Pocket PC / Windows Mobile** : versión ligera de Windows adaptada a móviles. 

**Años 2007–2010 – La revolución del smartphone** 

# **iOS (Apple)** 

- Nace con el **iPhone (2007)** . 

- Basado en el núcleo de **macOS (XNU + Darwin)** . 

- Interfaz fluida y tienda de apps cerrada (App Store). 

- Muy centrado en la **experiencia de usuario** . 

# **Android (Google)** 

- Primera versión pública en 2008. 

- Basado en el **kernel de Linux** con librerías específicas (como **Bionic** ). 

- Código abierto (AOSP), pero con servicios Google cerrados. 

- Arquitectura modular: capas HAL, ART (Android Runtime), etc. 

_Desde 2010 domina el mercado mundial, con fabricantes como Samsung, Xiaomi, Motorola, etc._ 

# **Otros sistemas que surgieron (y cayeron)** 

|**Sistema**|**Características principales**|**Estado actual**|
|---|---|---|
|**BlackBerry OS**|Fuerte en seguridad, teclado físico,<br>multitarea basada en Java|Obsoleto (reemplazado<br>por Android)|
|**Windows**<br>**Phone**|Fluido, interfaz Metro, mal soporte de<br>apps|Descontinuado (2017)|
|**webOS**<br>**(Palm/HP)**|Multitarea avanzada, interfaz de gestos|Sobrevive en smartTVs de<br>LG|

|**Tizen**<br>**(Samsung)**|Basado en Linux, usado en wearables y<br>TV|Muy limitado en<br>smartphones|



# **Arquitectura típica de un SO móvil (Android/iOS)** 

Un sistema operativo móvil se estructura en varias capas, cada una con funciones específicas. De arriba hacia abajo: 

1. **Aplicaciones del usuario** 

   - Aplicaciones instaladas por el usuario (ej. WhatsApp, Instagram, navegador). 

   - Interactúan con el sistema a través de APIs y servicios. 

2. **Framework de aplicaciones** 

   - Conjunto de bibliotecas y servicios que permiten desarrollar aplicaciones. 

   - Ejemplo: en Android incluye Activity Manager, Notification Manager, etc. 

3. **Librerías del sistema y entorno de ejecución** 

   - Conjunto de bibliotecas nativas (C/C++) y entornos de ejecución. 

   - En Android: Android Runtime (ART). 

   - En iOS: frameworks como UIKit y Foundation, con soporte para Swift y Objective-C. 

4. **Capa de abstracción del hardware (HAL)** 

   - Interfaz entre el sistema operativo y el hardware. 

   - Permite que el SO sea compatible con distintos chips y sensores sin modificar el núcleo. 

# 5. **Núcleo del sistema operativo (Kernel)** 

   - Android: kernel Linux. 

   - iOS: núcleo híbrido XNU (basado en Mach y BSD). 

   - Se encarga de la gestión de procesos, memoria, dispositivos y seguridad. 

6. **Hardware** 

   - Componente físico del dispositivo: procesador, memoria, almacenamiento, sensores, pantalla, etc. 

# **Seguridad en sistemas móviles** 

- **Sandboxing** de aplicaciones: aislamiento por defecto. 

- Permisos granulares por app (ej. micrófono, ubicación). 

- Cifrado completo del dispositivo. 

- Autenticación biométrica (huella, cara). 

- Actualizaciones OTA (Over The Air). 

# **Malware y gestión de dispositivos Android en entornos corporativos** 

- **Android sí puede sufrir malware** : troyanos (apps aparentemente legítimas que ocultan código malicioso, p. ej. troyanos bancarios), spyware, ransomware, adware… Los dispositivos infectados pueden formar parte de **botnets** y participar en **ataques DDoS** . 

- **Android es multiusuario** : cada aplicación se ejecuta con su propio **UID de Linux** en su propio proceso y **sandbox** , con separación de memoria y datos; además, desde Android 4.2 admite varios perfiles de usuario y **perfil de trabajo** (Android Enterprise). 

- Medidas: instalar solo desde tiendas oficiales, **Google Play Protect** , permisos mínimos, actualizaciones de seguridad y, en organizaciones, soluciones **MDM/EMM** (Mobile Device Management, p. ej. Microsoft Intune) para inventariar, configurar, aplicar políticas, bloquear y borrar en remoto los dispositivos corporativos. 

# **Comparativa de SO móviles actuales** 

|**Característica**|**Android**|**iOS**|
|---|---|---|
|**Código**|Abierto (AOSP) + cerrado (Google)|Cerrado (excepto kernel<br>Darwin)|
|**Dispositivos**|Diversos fabricantes|Solo iPhone / iPad|

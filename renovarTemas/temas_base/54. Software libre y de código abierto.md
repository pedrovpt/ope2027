# SOFTWARE LIBRE Y DE CÓDIGO ABIERTO

El software libre y de código abierto (FOSS) son conceptos clave en el ámbito de la informática, que promueven la libertad de los usuarios para ejecutar, estudiar, modificar y distribuir el software.

Su origen se encuentra en la evolución del modelo de negocio de la industria informática en los años 80, cuando la venta de software comenzó a ser más relevante que la de hardware, lo que permitió el surgimiento de proyectos como el GNU.

**Libre no significa gratuito.** El término inglés «free software» se refiere a libertad («free as in free speech, not as in free beer»). Un programa libre puede venderse; y un programa gratuito (freeware) puede ser privativo si no da acceso al código ni permite modificarlo. Software **privativo o propietario** es el que restringe alguna de esas libertades (p. ej. Windows, macOS, Oracle Database).

## Modelo de Desarrollo del Software Libre y de Código Abierto

  - **Modelo paralelo:**
    
      - Trabajo en varios equipos en diferentes áreas de un sistema.
    
      - Los esfuerzos no se ven como desperdicio; se valoran por su contribución a la calidad final.

  - **Comunidad global de desarrolladores:**
    
      - Involucra a grandes comunidades distribuidas globalmente.
    
      - Internet y redes de comunicación han facilitado esta colaboración.
    
      - Uso de herramientas de control de versiones ha contribuido a mejorar el proceso.

  - **Revisión por iguales:**
    
      - El código se envía a la comunidad de desarrolladores para recibir sugerencias y correcciones.
    
      - El equipo original puede incorporar estos cambios y reiniciar el ciclo de desarrollo.

  - **Retroalimentación temprana:**
    
      - Se pueden incorporar contribuciones de cualquier fuente.
    
      - Los usuarios son tratados como contribuyentes al desarrollo.
    
      - Ejemplo: en Linux, los fallos de seguridad se corrigen rápidamente, a veces en cuestión de horas.

  - **Ciclos cortos de lanzamiento:**
    
      - Se liberan nuevas versiones de manera frecuente, favorecida por la colaboración y retroalimentación constantes.

## Modelos de Negocio en el Software Libre y de Código Abierto

  - **Software privativo sobre Linux:**
    
      - Linux usa principalmente licencia GPL, permitiendo la inclusión de software privativo.
    
      - Ejemplo: Oracle distribuye su base de datos con Linux sin revelar su código, pero utiliza Linux para ganar mercado.
    
      - Oracle desarrolla Oracle Linux, una versión modificada de Linux con mejoras en seguridad y rendimiento.
    
      - Aunque las modificaciones al kernel se licencian bajo GPL, Oracle mantiene el código privativo de su base de datos.

  - **Soporte y servicios ligados al código abierto:**
    
      - Algunos distribuidores de Linux (como SuSE, Red Hat) obtenían ingresos vendiendo sus paquetes junto con soporte.
    
      - Ahora, muchos adoptan modelos de suscripción y servicios profesionales.
    
      - Ejemplo: Red Hat ofrece suscripciones para actualizaciones y soporte, mientras que Ubuntu usa Landscape para la gestión de servidores y escritorios.

  - **Mejora del software privativo mediante software de código abierto:**
    
      - El SW de código abierto mejora el SW privativo al permitir su integración.
    
      - Ejemplo: Zend Server usa Apache como servidor web, y Oracle emplea Apache en productos como Oracle HTTP Server y Weblogic.
    
      - Esta combinación de software privativo y de código abierto genera nuevas oportunidades de negocio.

  - **Modelo de negocio de licencia dual:**
    
      - El software se distribuye con dos licencias: una de código abierto y otra privativa/comercial.
    
      - Ejemplo: MySQL distribuye una versión básica (Community Edition) bajo GPL y versiones comerciales con características adicionales bajo licencia privativa.
    
      - Este modelo genera una comunidad de usuarios activos, lo que ayuda a innovar e incrementar el interés por el producto.

  - **Hardware y open source:**
    
      - El negocio se genera al combinar software de código abierto con hardware en configuraciones listas para usar.
    
      - Ejemplo: Ubuntu con Cloud OpenStack, Asterisk para servicios de telefonía, y dispositivos de electrónica de consumo como routers y discos duros de red que incluyen Linux y software GNU GPL.
    
      - Este enfoque appliance (hardware + software) se está expandiendo en diversas áreas, como servidores antivirus y sistemas de telefonía IP.

  - **Software como servicio (SaaS) sobre software libre:** un proveedor cloud puede montar un servicio sobre programas GPL y **cobrar por el servicio** (uso, consumo de recursos, soporte), pero **nunca por la licencia** del programa, ya que la GPL prohíbe exigir cuotas o royalties por ejercer los derechos que concede. Ver el apartado «La GPL en la nube» más abajo.

## Ejemplos de software libre, de código abierto y privativo

  - **Sistemas operativos de código abierto:** distribuciones GNU/Linux (**Ubuntu**, Debian, Fedora, openSUSE, Linux Mint, Guadalinex, GECOS…), familia BSD (FreeBSD, OpenBSD, NetBSD) y Android en su versión AOSP.

  - **Sistemas operativos privativos:** **Windows** (7, 10, 11, Windows Server) y **macOS** / iOS de Apple. Aunque el núcleo de macOS (Darwin/XNU) publica su código, el sistema completo es privativo.

  - **Ofimática:** LibreOffice (de The Document Foundation, licencia MPL 2.0) y Apache OpenOffice. Ambas usan como formato nativo ODF (OpenDocument, norma ISO/IEC 26300).

  - **Servidores, bases de datos y otras aplicaciones:** Apache HTTP Server, Tomcat, PostgreSQL, MySQL/MariaDB, Firefox, Thunderbird, GIMP, VLC, 7-Zip, KVM, VirtualBox (edición base).

### Apache OpenOffice

  - Paquete ofimático **de código abierto** mantenido por la **Apache Software Foundation**. Procede de OpenOffice.org (Sun Microsystems, luego Oracle), que Oracle cedió a Apache en 2011; LibreOffice nació como bifurcación (fork) de ese mismo proyecto en 2010.

  - Al ser código abierto, los usuarios pueden **estudiar, modificar y mejorar** el software según sus necesidades.

  - Se distribuye bajo **Licencia Apache 2.0** (no existe una «Apache 3.0»).

  - Es **multiplataforma**: Windows, GNU/Linux y macOS (no es exclusivo de Windows).

  - Componentes: Writer (textos), Calc (hoja de cálculo), Impress (presentaciones), Draw (dibujo), Base (bases de datos) y Math (fórmulas).

  - Permite **trabajo colaborativo** sobre documentos mediante control de cambios, comentarios, comparación de versiones y hojas de cálculo compartidas en Calc, aunque no ofrece coedición en tiempo real al estilo de las suites en la nube.

### Herramientas libres de soporte y gestión del puesto de trabajo

  - **UltraVNC:** software libre (licencia GPL) de **control remoto** basado en el protocolo VNC/RFB, para ver y manejar el escritorio de otro equipo.
    
      - El **servidor** se ejecuta en equipos **Microsoft Windows** y se usa como servicio de **mantenimiento a distancia (telemantenimiento)** de esos equipos.
    
      - Incluye un **visor Java** que puede incrustarse en un navegador web, lo que permite conectarse (y transferir archivos) **desde cualquier sistema operativo que soporte Java**. Por tanto, **no es correcto** afirmar que «funciona exclusivamente para sistemas Windows».
    
      - Está desarrollado en los lenguajes **C, C++ y Java**. Otras funciones: transferencia de ficheros, chat, cifrado mediante plugins, autenticación Windows.
    
      - Herramientas similares: TightVNC, TigerVNC; en Linux, el cliente Remmina.

  - **OCS Inventory NG:** software libre (GPL) de **inventario** automático de hardware y software mediante agentes instalados en los equipos.

  - **GLPI:** software libre (GPL) de **gestión del parque informático y centro de servicios** (incidencias, peticiones, activos). Se integra habitualmente con OCS Inventory.

  - **microCLAUDIA:** herramienta del **CCN-CERT** (Centro Criptológico Nacional) que actúa como «vacuna» de protección frente a ransomware en los equipos. **No** es una distribución Linux.

# EL PROYECTO GNU

  - El Proyecto GNU, iniciado por Richard Stallman en 1983, tenía como objetivo recuperar el espíritu colaborativo y la libertad de uso del software que prevalecía en los años 70 en los centros de investigación, antes de que las restricciones del software propietario limitaran este tipo de intercambio.

  - **Significado de GNU:** es un **acrónimo recursivo** de «**GNU's Not Unix**» («**GNU No es Unix**»). Indica que GNU es un **sistema operativo de tipo Unix** (compatible con Unix en su diseño y comportamiento) pero que **no es Unix**, porque no contiene código de Unix y es **software libre**. Su símbolo es el ñu.

  - Stallman anunció el proyecto en septiembre de 1983, el desarrollo comenzó en enero de 1984 y en 1985 publicó el **Manifiesto GNU**.

  - **GNU no se limita al sistema operativo base:** el proyecto incluye **también programas de aplicación** y utilidades. Ejemplos: el compilador **GCC**, el editor **Emacs**, el intérprete de órdenes **Bash**, la biblioteca **glibc**, las **coreutils**, **GnuPG**, **GIMP** (GNU Image Manipulation Program), el entorno de escritorio GNOME (nacido dentro del proyecto) o **GNU Health**.

  - **GNU y Linux:** GNU desarrolló su propio núcleo, **GNU Hurd**, que nunca llegó a estar listo para producción. Por eso GNU **se usa generalmente con el kernel Linux**, y la FSF defiende llamar al conjunto **GNU/Linux**.

  - Stallman definió cuatro libertades fundamentales para que un software sea considerado libre:
    
      - **Libertad 0:** La libertad de ejecutar el programa como se desea, con cualquier propósito
    
      - **Libertad 1:** La libertad de estudiar cómo funciona el programa, y cambiarlo para que haga lo que usted quiera (El acceso al código fuente es una condición necesaria para ello)
    
      - **Libertad 2:** La libertad de redistribuir copias para ayudar a su prójimo
    
      - **Libertad 3:** La libertad de distribuir copias de sus versiones modificadas a terceros.

  - En 1985, se fundó la Free Software Foundation (FSF), que tiene como misión promover el software libre y recaudar fondos para el proyecto GNU. El sistema operativo GNU/Linux, creado en colaboración con Linus Torvalds, es uno de los mayores éxitos derivados de este proyecto. Torvalds desarrolló un kernel basado en UNIX en 1991, que más tarde adoptó la licencia GNU GPL, promoviendo la libertad de modificar y distribuir el software.

  - Precisión: el kernel Linux se publicó en 1991 y adoptó la **GPL en 1992**; sigue licenciado bajo **GPL versión 2** (no ha pasado a GPLv3).

## Sistemas de ficheros soportados por GNU/Linux

  - GNU/Linux trabaja con sus **sistemas de ficheros nativos** (**ext2, ext3, ext4**, además de XFS, Btrfs, JFS, ReiserFS) y **también con sistemas de otros SO**, por lo que no está limitado a los nativos.

  - Soporta los sistemas de Microsoft **FAT** (FAT16/FAT32, vfat) y **exFAT**, y **NTFS** (mediante el controlador ntfs-3g o el controlador ntfs3 del kernel, con lectura y escritura).

  - Otros: ISO 9660 y UDF (medios ópticos), HFS+ (Apple), y sistemas de ficheros en red como **NFS** y **SMB/CIFS** (Samba).

  - Respuesta tipo examen: «GNU/Linux trabaja con sistemas de ficheros FAT y NTFS» es correcta. Son erróneas «sólo NTFS», «sólo con sus nativos (ext2, ext3)» y «con todos los sistemas con los que trabaje UNIX» (no existe esa equivalencia general).

## Licencia General Pública GNU (GPL)

  - La Licencia General Pública GNU (GPL) (General Public License) es una de las licencias más influyentes en el mundo del SW libre. Garantiza que los usuarios puedan ejecutar, modificar, distribuir y compartir SW, siempre bajo las mismas condiciones que aseguren estas libertades. El término "copyleft" se emplea como contraposición al "copyright", destacando el objetivo de proteger estas libertades a lo largo del tiempo.

  - **Versiones:** GPLv1 (1989), GPLv2 (1991) y **GPLv3 (29 de junio de 2007)**. Variantes de la familia: **LGPL** (Lesser GPL, copyleft débil pensado para bibliotecas, permite enlazarlas desde software privativo) y **AGPL** (Affero GPL, extiende la obligación de ofrecer el código al uso a través de red).

**Licencia GNU GPL (versión 3): cumple los siguientes derechos regulados:**

  - **Ejecución ilimitada:** Derecho de ejecutar el programa en cualquier número de computadoras, sin limitaciones.

  - **Distribución de programas no modificados:**
    
      - Se permite distribuir programas sin modificar, con la intención de ayudarlos en su ejecución o modificación.
    
      - No se pueden hacer copias fuera del acuerdo inicial con el proveedor.

  - **Prohibición de restricción de derechos de copia:** No se puede restringir el derecho de copia de los usuarios ni usar sistemas anti-copia que limiten esos derechos.

  - **Distribución de copias no modificadas del código fuente:**
    
      - Se puede distribuir sin modificar el código fuente, manteniendo el copyright y la licencia original.
    
      - Se puede cobrar o no por la distribución, además de ofrecer soporte o garantías por una cuota.

  - **Distribución de copias modificadas:**
    
      - Debe indicarse la fecha de modificación.
    
      - El trabajo (original y modificado) debe licenciarse bajo la misma licencia GPL.
    
      - No se puede aplicar una licencia restrictiva a obras combinadas con la obra GPL.

  - **Acceso al código fuente en productos físicos:**
    
      - Si el código objeto está embebido en un producto físico, debe incluirse en un medio duradero o con una oferta escrita para acceder a él a un costo razonable.
    
      - En productos electrónicos de consumo, debe incluir instrucciones de instalación.

  - **Prohibición de restricciones adicionales:**
    
      - No se permite ninguna restricción sobre los derechos establecidos por la licencia, incluyendo el cobro de cuotas por la licencia o derechos asociados.

  - **Licencia expresa de patentes (sección 11 GPLv3):** cada contribuidor concede a los usuarios una licencia de patente sobre sus aportaciones, y quien inicie un litigio de patentes contra el programa pierde sus derechos.

### Cobrar por distribuir frente a cobrar royalties (GPLv3)

  - **Permitido:** cobrar el precio que se quiera (o nada) **por cada copia que se distribuye**, y cobrar por soporte, garantía o servicios.

  - **Prohibido:** imponer una **cuota de licencia, royalty** u otro cargo **por ejercer los derechos** que concede la GPL (ejecutar, copiar, modificar, redistribuir) (sección 10 GPLv3). Quien recibe una copia puede redistribuirla libremente sin pagar nada al autor.

  - Por tanto, la afirmación «la GPLv3 permite cobrar royalties por la redistribución del software sin modificaciones» es **FALSA**.

### La GPL en la nube (SaaS)

  - La GPL solo impone obligaciones al **distribuir** («transmitir») copias. La GPLv3 aclara que la mera interacción con un usuario a través de una red, sin transferirle una copia, no es distribución.

  - Un proveedor cloud que implanta un programa GPL y lo ofrece como servicio propio **puede cobrar por el servicio** (por uso, por consumo de recursos, suscripción, soporte) y también ofrecerlo gratis, pero **no puede cobrar por la licencia** del producto.

  - Como no distribuye el programa, la GPL **no le obliga a publicar sus modificaciones** (la llamada «laguna ASP» o «SaaS loophole»). Para cerrar esa laguna se creó la **GNU AGPLv3**, que obliga a ofrecer el código fuente a los usuarios que interactúan con el programa a través de la red.

# TIPOS DE LICENCIAS DE SOFTWARE LIBRE Y DE CÓDIGO ABIERTO

  - **Licencias permisivas** (sin copyleft): permiten incorporar el código a software privativo, exigiendo básicamente conservar el aviso de copyright. Ejemplos: **MIT**, **BSD** (2 y 3 cláusulas) y **Apache 2.0**.

  - **Copyleft débil:** las modificaciones del propio componente deben seguir siendo libres, pero puede combinarse con código privativo. Ejemplos: **LGPL**, **MPL 2.0** (Mozilla).

  - **Copyleft fuerte:** toda obra derivada debe distribuirse bajo la misma licencia. Ejemplos: **GPL** y **AGPL**.

  - **EUPL (Licencia Pública de la Unión Europea):** licencia copyleft creada por la Comisión Europea (v1.0 en 2007, v1.2 en 2017), disponible en todas las lenguas oficiales de la UE y compatible con otras licencias (GPL, MPL, LGPL…). Es la recomendada para liberar software de las Administraciones Públicas.

  - **Licencias privativas (NO son de código abierto):** las licencias comerciales de Oracle (por ejemplo, la «Licencia Oracle» / Oracle Technology Network para Oracle Database), los contratos de licencia de usuario final (EULA) de Microsoft, etc. No dan acceso al código ni permiten modificarlo o redistribuirlo.

**Comparativa de licencias y concesión expresa de patentes:**

| **Licencia**        | **Tipo**              | **Licencia expresa de patentes** | **Observaciones**                                                                                          |
| ------------------- | --------------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| MIT                 | Permisiva             | **No**                           | Muy breve; solo exige mantener el aviso de copyright.                                                      |
| BSD (2/3 cláusulas) | Permisiva             | No                               | La de 3 cláusulas prohíbe usar el nombre del autor para promocionar derivados.                             |
| Apache 2.0          | Permisiva             | Sí                               | Concesión expresa de patentes y cláusula de terminación si se litiga. Compatible con GPLv3 (no con GPLv2). |
| GNU GPLv2           | Copyleft fuerte       | No explícita                     | Licencia del kernel Linux.                                                                                 |
| GNU GPLv3           | Copyleft fuerte       | Sí                               | Añade patentes, anti-tivoización y protección frente a DRM.                                                |
| GNU LGPLv3          | Copyleft débil        | Sí                               | Se construye sobre la GPLv3, por lo que hereda su cláusula de patentes.                                    |
| GNU AGPLv3          | Copyleft fuerte (red) | Sí                               | Obliga a ofrecer el código a usuarios que usan el programa por red.                                        |
| MPL 2.0             | Copyleft débil        | Sí                               | Copyleft a nivel de fichero (LibreOffice, Firefox).                                                        |

# INICIATIVAS SIMILARES: OPEN SOURCE INITIATIVE (OSI) Y LICENCIAS DE CÓDIGO ABIERTO

  - Aunque el concepto de SW libre ha sido promovido por la FSF, en 1998 surgió la Open Source Initiative (OSI), liderada por Eric Raymond, que intentó hacer el SW libre más atractivo para el ámbito empresarial al enfocarse en el código abierto. La OSI define el código abierto a través de criterios que incluyen la disponibilidad del código fuente, la libertad de modificación, la no discriminación y la neutralidad tecnológica.

  - **Misión de OSI:** OSI es una organización sin ánimo de lucro que promueve, educa y crea conciencia sobre la importancia del software no propietario.

  - **Open Source Definition (OSD):** La OSD es la definición clave de OSI para el código abierto y establece los siguientes elementos para una licencia de código abierto:
    
      - **Distribución y venta:** La licencia no debe restringir la distribución ni la venta del software, tanto individualmente como parte de una obra agregada de diversas fuentes. No se pueden cobrar cuotas ni royalties por la venta.
    
      - **Código fuente accesible:** El software debe incluir su código fuente y permitir la distribución tanto del código fuente como del código compilado. Si el código fuente no se distribuye con el software, debe haber un procedimiento para obtenerlo a un costo razonable, preferiblemente gratuito a través de Internet.
    
      - **Modificaciones y trabajos derivados:** Se deben permitir modificaciones y trabajos derivados del software, así como distribuirlos bajo la misma licencia del trabajo original.
    
      - **Integridad de la autoría:** La licencia puede restringir la distribución de código modificado solo si permite la distribución de archivos de parche junto con el código fuente original. Debe permitir la distribución del software construido a partir de código fuente modificado.
    
      - **No discriminación de personas o grupos:** La licencia no debe discriminar a ningún individuo o grupo.
    
      - **Uso en cualquier campo de aplicación:** La licencia no puede restringir el uso del software en ámbitos comerciales o de investigación.
    
      - **No se requiere licencia adicional:** La licencia otorgada no debe exigir una licencia adicional para usar el software.
    
      - **Compatibilidad con otros software:** La licencia no puede imponer restricciones a otros software distribuido junto al código abierto.
    
      - **Neutralidad tecnológica:** La licencia debe ser tecnológicamente neutral, sin favorecer una tecnología o interfaz específica.

  - Todas las licencias de la tabla anterior (MIT, BSD, Apache, GPL, LGPL, AGPL, MPL, EUPL) están aprobadas por la OSI como licencias de código abierto.

# VENTAJAS DEL SOFTWARE LIBRE

  - **Acceso sin restricciones:** El software puede descargarse, probarse y modificarse sin costes adicionales.

  - **Soporte comunitario:** Las comunidades detrás de proyectos de SW libre ofrecen soporte gratuito, aunque puede ser limitado en proyectos menos populares.

  - **Estándares abiertos:** El software libre suele ser compatible con otros sistemas que siguen los mismos estándares.

  - **Seguridad:** El acceso al código fuente permite una revisión constante, mejorando la seguridad.

# INCONVENIENTES DEL SOFTWARE LIBRE

  - **Desarrollo en sistemas de escritorio:** Aunque el software libre es dominante en servidores, en los sistemas de escritorio su adopción es menor, especialmente en el ámbito de los usuarios no técnicos.

  - **Soporte técnico:** El soporte urgente puede ser limitado, aunque se puede contratar servicios profesionales.

  - **Usabilidad:** Algunas aplicaciones de software libre tienen una usabilidad inferior a la de sus contrapartes comerciales.

  - **Conocimiento técnico:** El uso efectivo de software libre a menudo requiere conocimientos técnicos, lo que puede ser una barrera para algunos usuarios o empresas.

# PROYECTOS AUTONÓMICOS PARA LA ADOPCIÓN DE SOFTWARE LIBRE Y DE CÓDIGO ABIERTO EN EL ÁMBITO SANITARIO PÚBLICO ANDALUZ

La adopción del SW libre y de código abierto (FOSS) ha demostrado ser una estrategia valiosa para la Administración Pública, especialmente en sectores como la sanidad, donde la eficiencia y la reducción de costos son esenciales.

## Marco normativo andaluz del software libre

  - **Decreto 72/2003, de 18 de marzo**, de Medidas de Impulso de la Sociedad del Conocimiento en Andalucía: incluye el fomento de la difusión y utilización del software libre (de él nace Guadalinex).

  - **Orden de 21 de febrero de 2005**, sobre disponibilidad pública de los programas informáticos de la Administración de la Junta de Andalucía y de sus Organismos Autónomos (Consejería de Innovación, Ciencia y Empresa; BOJA nº 49, de 10/03/2005). Contenido:
    
      - **Art. 1. Objeto:** poner a disposición pública el código fuente y la documentación de los programas propiedad de la Junta y sus Organismos Autónomos, que tendrán carácter de software libre, y fijar las condiciones de su libre uso y distribución.
    
      - **Art. 2. Definición de software libre:** programas y documentación que puedan (a) leerse y/o ejecutarse para cualquier finalidad sin restricciones, (b) copiarse y modificarse libremente y (c) difundirse libremente con sus versiones modificadas. **Apartado 2: tienen consideración de software libre tanto el producido por el personal de la Junta o sus Organismos Autónomos en el ejercicio de sus funciones como el elaborado a medida para ellos mediante cualquier modalidad de contrato con terceros.**
    
      - **Art. 3. Condiciones de uso:** el software estará disponible en forma de código fuente y la documentación en un **formato abierto que permita su modificación**; la difusión y uso de copias, modificadas o no, solo se autoriza si se mantienen esas condiciones. (La Orden **no** menciona ninguna plataforma concreta como SIGC.)
    
      - **Art. 4. Proceso de liberación:** se habilitarán las **infraestructuras informáticas necesarias** para publicar el código, la documentación y sus modificaciones (la Orden no las identifica con ninguna plataforma con nombre, como «GUIA»). El repositorio así constituido **podrá albergar y/o referenciar** código y documentación liberados por **otras Administraciones públicas**.
    
      - **Art. 5. Excepciones:** por causas justificadas, la Dirección General de Innovación y Administraciones Públicas puede restringir total o parcialmente la liberación o limitar su ámbito de difusión.
    
      - **Disposiciones:** la DG de Innovación y AA.PP. fijará los modelos concretos de licencia; la liberación será progresiva con un plazo máximo de **un año**; entrada en vigor al día siguiente de su publicación en el BOJA.

  - En cumplimiento de esta Orden se creó el **Repositorio de Software Libre de la Junta de Andalucía**, junto con el marco de desarrollo **MADEJA** y el Catálogo de Software. Hoy la publicación se hace a través del portal «Desarrollo de servicios digitales» de la Junta.

  - **Ámbito estatal:** el art. 157 de la Ley 40/2015 obliga a las Administraciones a poner a disposición de otras las aplicaciones de su propiedad, que pueden declararse de fuentes abiertas (licencia EUPL), y el art. 158 regula el **Centro de Transferencia de Tecnología (CTT)**.

## Guadalinex y GECOS

  - **Guadalinex:** distribución GNU/Linux de la Junta de Andalucía orientada a la ciudadanía y a los centros educativos (basada inicialmente en Debian y después en Ubuntu).

  - **GECOS** (Guadalinex Escritorio COrporativo eStándar): distribución Linux para el **puesto de trabajo del empleado público**, con un amplio **catálogo de aplicaciones de puesto** y un **centro de control (GECOS Control Center)** que permite **administrar los equipos de forma remota y centralizada desde una interfaz web**. Fue desarrollada por la Consejería de Hacienda y Administración Pública con SANDETEL y hoy su ámbito corresponde a la **Agencia Digital de Andalucía (ADA)**.

  - Distractores habituales: **OCS Inventory** (inventario), **GLPI** (gestión de parque y helpdesk) y **microCLAUDIA** (vacuna antiransomware del CCN-CERT) no son distribuciones Linux.

## Proyectos de integración de software libre en la sanidad pública andaluza

La Junta de Andalucía ha sido pionera en la incorporación de software libre y de código abierto en sus sistemas informáticos. Esto incluye tanto la infraestructura tecnológica como las aplicaciones utilizadas por los profesionales de la salud.

  - **Sistema Sanitario Público de Andalucía (SSPA):** Este sistema ha adoptado soluciones basadas en software de código abierto en varias de sus plataformas tecnológicas, lo que ha permitido mejorar varios aspectos en la gestión de la atención sanitaria y la infraestructura tecnológica. Herramientas como Linux, Apache, MySQL/PostgreSQL, OpenEHR, LibreOffice y KVM/VirtualBox han transformado la infraestructura tecnológica del SSPA.

  - **OpenEHR para la gestión de registros médicos electrónicos:** es una plataforma de código abierto especializada en la gestión de registros médicos electrónicos (EMR). Esta plataforma se basa en estándares abiertos que permiten almacenar, compartir y gestionar datos clínicos de los pacientes de manera interoperable entre diferentes sistemas. En la Junta de Andalucía, el uso de OpenEHR ha sido clave para asegurar la interoperabilidad de los datos de salud a lo largo del sistema sanitario público andaluz.

  - **GNU Health:** es una solución de código abierto diseñada para la gestión de la salud pública y la atención primaria. Este sistema abarca desde la gestión de registros médicos electrónicos hasta la administración de centros de salud, incluyendo aspectos de salud pública, como el seguimiento de epidemias y el análisis de datos sanitarios. Se ha utilizado en varias áreas de Andalucía, en particular en la atención primaria y en programas de salud pública. Su integración dentro del SSPA ha permitido optimizar la gestión de los pacientes, facilitar el acceso a la historia clínica electrónica y asegurar que los profesionales sanitarios tengan una visión completa y precisa de la salud del paciente.

## Beneficios para la administración sanitaria

  - **Reducción de costos:** Al evitar los elevados costos de las licencias de software propietario, las Administraciones Públicas pueden destinar más recursos a la infraestructura básica y mejorar los servicios en la atención sanitaria.

  - **Interoperabilidad:** La interoperabilidad entre diferentes sistemas es crucial en el ámbito sanitario. Las soluciones basadas en estándares abiertos permiten que los distintos sistemas de información sanitaria (SIS) en hospitales y centros de salud interactúen de manera eficiente.

  - **Personalización y adaptabilidad:** El software libre permite la modificación de las aplicaciones para adaptarlas a las necesidades específicas de cada institución, garantizando una mayor flexibilidad.

## Iniciativas autonómicas e impulsos legislativos

A nivel autonómico, Andalucía sigue los principios establecidos por iniciativas legislativas como:

  - El Esquema Nacional de Interoperabilidad y la Licencia Pública Europea (EUPL), que facilitan la adopción de software libre y garantizan la reutilización y la interoperabilidad entre administraciones.

  - El Centro Nacional de Referencia de Aplicación de las TIC Basadas en Fuentes Abiertas (CENATIC)

  - Otras entidades como el Observatorio Nacional del Software de Fuentes Abiertas (ONSFA), promueven políticas de software abierto que pueden ser implementadas en el ámbito sanitario público, fomentando la colaboración entre distintas administraciones y optimizando los recursos disponibles.

## Proyectos de colaboración y apoyo a la investigación

Los proyectos de software libre en Andalucía también se benefician de las iniciativas de investigación, un área que ha experimentado un crecimiento en los últimos años, tanto a nivel local como internacional. El desarrollo colaborativo de aplicaciones de salud y la investigación en nuevas soluciones tecnológicas se potencia mediante el uso de software libre, donde se facilita la participación de expertos, profesionales sanitarios y comunidades académicas.

## Desafíos y barreras

La adopción de software libre en la sanidad pública andaluza aún enfrenta varios retos. La falta de formación en el uso y gestión de estas soluciones tecnológicas es una de las principales barreras. Según estudios realizados por CENATIC, una parte significativa de los profesionales TIC de las administraciones sanitarias reportan un conocimiento limitado de las tecnologías de código abierto. Además, los costes de migración y la adaptación de software existente a nuevas plataformas de código abierto son factores que aún ralentizan la plena adopción.

## El futuro del software libre en la sanidad pública

El impulso hacia la digitalización de la sanidad y la incorporación de tecnologías emergentes, como la inteligencia artificial y el análisis de datos masivos, refuerzan la necesidad de contar con sistemas abiertos y transparentes. A medida que la infraestructura tecnológica en Andalucía y otras regiones avanzan, es probable que el uso de software libre siga aumentando, con el respaldo de políticas autonómicas y nacionales que fomenten su adopción. La colaboración entre administraciones, el sector privado y las universidades será clave para garantizar que el software libre siga creciendo como una alternativa viable en el ámbito sanitario.

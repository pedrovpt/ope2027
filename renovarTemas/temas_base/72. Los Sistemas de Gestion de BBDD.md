# TEMA 72: SISTEMAS DE GESTIÓN DE BASES DE DATOS

## 1\. Concepto y funciones

Un SGBD o DBMS es el software que actúa como interfaz entre bases de datos, aplicaciones y usuarios. Permite definir estructuras, almacenar y consultar datos, controlar accesos, mantener integridad, gestionar transacciones y recuperar información tras fallos.

Funciones principales:

\- atender peticiones de definición y manipulación;

\- mantener el diccionario de datos;

\- gestionar transacciones y concurrencia;

\- aplicar restricciones de integridad;

\- controlar usuarios y permisos;

\- realizar copias y recuperación;

\- optimizar consultas y mantener estadísticas;

\- proporcionar independencia lógica y física.

El SGBD aplica políticas de seguridad e integridad definidas por la organización y el DBA, pero no define por sí mismo esas políticas.

Lenguajes:

\- \*\*DDL:\*\* CREATE, ALTER, DROP, TRUNCATE;

\- \*\*DML:\*\* SELECT, INSERT, UPDATE, DELETE, MERGE;

\- \*\*DCL:\*\* GRANT y REVOKE;

\- \*\*TCL:\*\* COMMIT, ROLLBACK, SAVEPOINT y SET TRANSACTION.

Usuarios: finales, desarrolladores, diseñadores y administradores de bases de datos (DBA).

## 2\. Modelos de datos

### 2.1. Relacional

Organiza la información en tablas, filas y columnas. Usa claves primarias, claves foráneas y SQL. Es adecuado para sistemas transaccionales que requieren integridad y consistencia.

Ejemplos: Oracle, SQL Server, MariaDB, MySQL, PostgreSQL y SQLite.

PostgreSQL se considera habitualmente objeto-relacional, aunque es compatible con el modelo relacional.

### 2.2. NoSQL

Las bases NoSQL manejan datos estructurados, semiestructurados o no estructurados mediante esquemas flexibles y escalabilidad horizontal.

\- \*\*Clave-valor:\*\* Redis, DynamoDB.

\- \*\*Documental:\*\* MongoDB, CouchDB; documentos JSON/BSON.

\- \*\*Grafos:\*\* Neo4j; nodos y relaciones, adecuado para redes sociales.

\- \*\*Columnar:\*\* Cassandra, HBase; adecuado para grandes volúmenes y análisis.

\- \*\*Objetos:\*\* db4o, ObjectDB; persisten objetos con encapsulación, herencia e identidad propia.

NoSQL suele utilizar escalabilidad horizontal y puede priorizar disponibilidad y tolerancia a particiones sobre consistencia inmediata, conforme a BASE.

### 2.3. CAP

En un sistema distribuido no es posible garantizar simultáneamente consistencia, disponibilidad y tolerancia a particiones. Ante una partición hay que priorizar consistencia o disponibilidad:

\- sistemas AP: responden aunque algunas lecturas sean temporalmente antiguas;

\- sistemas CP: mantienen consistencia, aunque pueden rechazar o retrasar peticiones.

### 2.4. Bases documentales

MongoDB permite documentos anidados, arrays, índices secundarios y esquemas flexibles. No proporciona integridad referencial automática equivalente a una clave foránea relacional cuando se usan referencias entre colecciones.

En consultas sobre arrays de subdocumentos, dos condiciones pueden satisfacerse en elementos distintos. Para exigir que se cumplan en el mismo elemento se utiliza \`$elemMatch\`.

### 2.5. Bases orientadas a objetos

Utilizan objetos, identidad (OID), encapsulamiento, herencia y polimorfismo. Sus relaciones se representan mediante referencias u OID, no mediante claves foráneas.

ODMG define ODL para definición y OQL para consultas. No dependen de SQL. Son adecuadas para CAD, SIG, multimedia y datos complejos.

Cuando una aplicación orientada a objetos utiliza una base relacional se necesita una capa ORM o motor de persistencia, como Hibernate, JPA, Entity Framework o SQLAlchemy.

## 3\. Arquitecturas

### 3.1. Centralizada

Toda la base reside en un único sistema. Facilita administración, pero presenta punto único de fallo, límites de escalabilidad y dependencia del servidor central.

### 3.2. Distribuida

Los datos se almacenan o replican en varios nodos. Puede ser homogénea o heterogénea. Mejora disponibilidad y rendimiento, pero requiere coordinación, replicación, sincronización y control de consistencia.

### 3.3. Federada

Integra bases autónomas que mantienen su independencia y cooperan mediante esquemas o vistas globales.

\- \*\*Federación fuertemente acoplada:\*\* existe un administrador global y uno o más esquemas federados.

\- \*\*Federación débilmente acoplada:\*\* los usuarios crean y mantienen federaciones mediante vistas.

La federación proporciona integración lógica sin consolidación física.

### 3.4. Escalabilidad y alta disponibilidad

\- \*\*Vertical:\*\* más CPU, RAM o almacenamiento en un servidor.

\- \*\*Horizontal:\*\* más servidores o nodos distribuyen la carga.

\- \*\*Elástica:\*\* recursos automáticos en la nube.

Alta disponibilidad:

\- \*\*activo-pasivo:\*\* un nodo trabaja y otro espera;

\- \*\*activo-activo:\*\* varios nodos trabajan simultáneamente.

Oracle RAC, MySQL Group Replication/InnoDB Cluster y MariaDB Galera pueden proporcionar escenarios activo-activo. Requieren comunicación entre nodos con latencia muy baja; no existe un mínimo general obligatorio de 10 Gbps.

## 4\. Motores de indexación

\- \*\*B+ tree:\*\* árbol balanceado multirrama, adecuado para búsquedas, ordenación y rangos.

\- \*\*Hash:\*\* localiza por función hash y es adecuado para igualdad, no para rangos.

\- \*\*Bitmap:\*\* apropiado para columnas de baja cardinalidad y consultas analíticas.

\- \*\*Índices compuestos:\*\* combinan varias columnas.

No conviene indexar todas las columnas: los índices aceleran lecturas, pero ralentizan escrituras y consumen espacio. La desnormalización controlada, estadísticas actualizadas y planes de ejecución ayudan a optimizar consultas.

Un plan de ejecución describe cómo procesará el SGBD una consulta: accesos, índices, joins y costes. Oracle permite consultarlo con \`EXPLAIN PLAN\`, \`DBMS\_XPLAN\` o herramientas gráficas.

Un \*\*HINT\*\* es un comentario especial, como \`/\*+ INDEX(...) \*/\`, que orienta al optimizador.

## 5\. Modelo ANSI/SPARC

La arquitectura ANSI/SPARC separa:

1\. \*\*Nivel externo:\*\* vistas personalizadas de cada usuario.

2\. \*\*Nivel conceptual:\*\* esquema lógico global con entidades, relaciones y restricciones.

3\. \*\*Nivel interno:\*\* almacenamiento físico, estructuras y métodos de acceso.

Proporciona independencia lógica y física. El diccionario de datos almacena metadatos, incluyendo definiciones de tipos, esquemas y correspondencias entre niveles.

## 6\. Transacciones y propiedades ACID

Una transacción es un conjunto de operaciones que se ejecutan como una unidad.

\- \*\*Atomicidad:\*\* todo o nada.

\- \*\*Consistencia:\*\* lleva la base de un estado válido a otro válido.

\- \*\*Aislamiento:\*\* las transacciones concurrentes no interfieren indebidamente.

\- \*\*Durabilidad:\*\* los cambios confirmados persisten tras fallos.

\`COMMIT\` confirma y hace permanentes los cambios. \`ROLLBACK\` deshace cambios no confirmados. \`SAVEPOINT\` marca un punto intermedio. \`TRUNCATE\` es DDL y puede provocar commit implícito según el SGBD.

## 7\. Concurrencia y bloqueos

\- \*\*Compartido:\*\* varias transacciones pueden leer; ninguna puede modificar mientras se mantenga el bloqueo.

\- \*\*Exclusivo:\*\* una transacción modifica y bloquea el acceso incompatible.

\- \*\*Pesimista:\*\* bloquea al seleccionar para actualizar, por ejemplo \`SELECT ... FOR UPDATE\`.

\- \*\*Optimista:\*\* no bloquea al leer y verifica versiones antes de confirmar.

El protocolo 2PL tiene:

\- fase de expansión: adquiere bloqueos;

\- fase de contracción: libera bloqueos y no adquiere nuevos.

Anomalías: lectura sucia, lectura no repetible, lectura fantasma y actualización perdida.

Niveles ANSI: READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ y SERIALIZABLE.

Timestamp ordering, wait-die, wound-wait, detección de ciclos y MVCC ayudan a reducir o resolver deadlocks.

## 8\. Recuperación de errores

\- \*\*WAL:\*\* registra cambios antes de aplicarlos y permite deshacer o rehacer.

\- \*\*Checkpoint:\*\* fija un punto de recuperación y reduce el trabajo tras un fallo.

\- \*\*Shadow paging:\*\* conserva versiones antiguas hasta confirmar.

\- \*\*Rollback:\*\* revierte una transacción no confirmada.

\- \*\*Redo:\*\* reaplica cambios confirmados.

Copias:

\- completa;

\- incremental;

\- diferencial;

\- física;

\- lógica;

\- en frío o en caliente.

En Oracle, RMAN realiza copias consistentes y recuperación. ARCHIVELOG conserva redo logs archivados y permite recuperación hasta el último commit o hasta un momento concreto. RSYNC no sustituye a RMAN para una copia consistente de una base abierta.

## 9\. Integridad

\- \*\*De entidad:\*\* clave primaria única y no nula.

\- \*\*Referencial:\*\* claves foráneas válidas.

\- \*\*De dominio:\*\* valores dentro de tipos, rangos o conjuntos permitidos.

\- \*\*Reglas de negocio:\*\* condiciones específicas de la organización.

## 10\. Oracle y herramientas

\- \*\*Tablespace:\*\* espacio lógico que agrupa datafiles.

\- \*\*Listener:\*\* proceso de red que escucha conexiones de clientes.

\- \*\*Puerto Oracle habitual:\*\* TCP 1521.

\- \*\*SQL\*Plus:\*\* ejecución interactiva o mediante scripts SQL/PLSQL.

\- \*\*SQL Developer:\*\* herramienta gráfica.

\- \*\*SQL Server Management Studio:\*\* administración gráfica de SQL Server.

\- \*\*pgAdmin:\*\* PostgreSQL.

\- \*\*MySQL Workbench:\*\* MySQL/MariaDB.

\- \*\*RMAN:\*\* backup y recuperación.

\- \*\*Data Pump:\*\* exportación e importación lógica.

\- \*\*APEX:\*\* SQL Workshop administra objetos; App Builder crea aplicaciones.

Oracle utiliza parámetros NLS para idioma, territorio, moneda, fechas y separadores. En España son coherentes la coma decimal y el euro; el dólar como moneda sería una configuración incorrecta para el entorno descrito.

DBeaver y SQuirreL SQL Client son herramientas cliente, no SGBD. Pueden consultar la base de datos de Mirth Connect, pero no deben utilizarse para modificar directamente canales o transformaciones en producción.

## 11\. Aplicación sanitaria

Los sistemas sanitarios combinan bases relacionales para transacciones clínicas, bases documentales para datos semiestructurados, bases de grafos para relaciones complejas y bases distribuidas para disponibilidad entre centros.

La selección depende de consistencia, disponibilidad, volumen, latencia, tipo de consulta, regulación, continuidad y capacidad de recuperación.

## 12\. Resumen para examen

\- MongoDB es documental; Apache HBase es NoSQL columnar; Neo4j es de grafos.

\- PostgreSQL es objeto-relacional; Oracle, SQL Server y MySQL son relacionales.

\- ODL define objetos y OQL consulta bases orientadas a objetos.

\- La federación integra bases autónomas sin consolidarlas físicamente.

\- ANSI/SPARC tiene niveles externo, conceptual e interno.

\- El diccionario de datos contiene la definición de tipos y metadatos.

\- ACID significa atomicidad, consistencia, aislamiento y durabilidad.

\- COMMIT confirma; ROLLBACK deshace; SAVEPOINT marca un punto.

\- Bitmap es adecuado para baja cardinalidad; B+ para rangos; hash para igualdad.

\- 2PL separa expansión y contracción.

\- WAL registra antes de escribir; shadow paging conserva versiones; RMAN recupera Oracle.

\- Oracle Listener usa habitualmente TCP 1521.

\- SQL\*Plus ejecuta SQL y PL/SQL; APEX SQL Workshop gestiona bases.

\- Los índices no deben crearse indiscriminadamente.

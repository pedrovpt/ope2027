# TEMA 73: EL MODELO RELACIONAL

## 1. Concepto y diseño

El modelo relacional, propuesto por Edgar F. Codd en 1970, organiza los datos en relaciones o tablas. Una tabla contiene tuplas o filas y atributos o columnas. Se apoya en teoría de conjuntos y lógica de predicados.

El diseño se divide en:

1. **Conceptual:** entidades, atributos y relaciones mediante E-R.
2. **Lógico:** transformación a tablas, claves y restricciones.
3. **Físico:** almacenamiento, índices, particiones y métodos de acceso.

Una relación tiene nombre, atributos, dominio para cada atributo, cardinalidad igual al número de filas y grado igual al número de columnas. El orden de filas y columnas no tiene significado lógico y las tuplas no deben duplicarse.

### 1.1. Claves e integridad

- **Superclave:** conjunto que identifica de forma única una tupla.
- **Clave candidata:** superclave mínima, única y no nula.
- **Clave primaria:** clave candidata elegida para identificar filas.
- **Clave alternativa:** candidata no escogida como primaria.
- **Clave foránea:** referencia una clave de otra tabla.

La integridad de entidad exige una clave primaria única y no nula. La integridad referencial exige que una clave foránea corresponda a una clave existente o sea nula cuando se permita.

Pueden violarse mediante INSERT o UPDATE de una referencia inexistente y DELETE o UPDATE de una fila padre referenciada. SELECT nunca modifica la integridad.

Acciones referenciales: RESTRICT/NO ACTION, CASCADE, SET NULL y SET DEFAULT.

Una restricción `DEFERRABLE INITIALLY DEFERRED` se comprueba al hacer COMMIT, no inmediatamente después de cada sentencia.

## 2. Modelo entidad-relación

- **Entidad:** objeto del mundo real.
- **Atributo:** propiedad de una entidad.
- **Relación:** asociación entre entidades.
- **Entidad débil:** depende de otra para identificarse.
- **Cardinalidades:** 1:1, 1:N y N:M.
- **Participación:** mínima y máxima, como (0,N) o (1,1).

Transformación a tablas:

- cada entidad genera una tabla;
- una relación 1:N propaga la clave del lado 1 al lado N;
- una relación N:M genera una tabla intermedia con ambas claves como clave primaria compuesta;
- una relación 1:1 puede resolverse propagando una clave o fusionando tablas;
- los atributos de una relación pasan a la tabla correspondiente;
- una entidad débil incluye la clave de su entidad fuerte.

Ejemplo: PROFESORES 1:N CURSOS y CURSOS N:M ALUMNOS producen cuatro tablas: Profesores, Cursos, Alumnos y Cursa. Imparte no necesita tabla porque es 1:N.

## 3. Normalización

La normalización reduce redundancia y anomalías de inserción, modificación y borrado mediante dependencias funcionales.

- **Dependencia funcional:** X determina Y si un valor de X determina un único valor de Y.
- **Dependencia parcial:** un atributo depende de parte de una clave compuesta.
- **Dependencia transitiva:** un atributo no clave depende de otro atributo no clave.

Formas normales:

- **1FN:** valores atómicos, sin grupos repetidos y filas identificables.
- **2FN:** 1FN y ningún atributo no clave depende solo de parte de una clave compuesta.
- **3FN:** 2FN y ausencia de dependencias transitivas.
- **BCNF/FNBC:** todo determinante es clave candidata. Se sitúa entre 3FN y 4FN.
- **4FN:** elimina dependencias multivaluadas no triviales.
- **5FN:** elimina dependencias de unión que no estén justificadas por claves.

La desnormalización puede usarse conscientemente para mejorar el rendimiento de consultas complejas, introduciendo redundancia controlada.

## 4. Álgebra y cálculo relacional

El álgebra relacional es procedimental: indica cómo obtener el resultado mediante operaciones sobre relaciones.

Operaciones básicas:

- selección `σ`: filtra filas;
- proyección `π`: selecciona columnas;
- unión `∪`;
- diferencia `−`;
- producto cartesiano `×`;
- renombrado `ρ`.

Operaciones derivadas: join, intersección y división. Un join equivale conceptualmente a producto cartesiano seguido de selección.

El cálculo relacional es declarativo: indica qué datos se desean, no cómo obtenerlos. El cálculo de tuplas usa variables de tupla y el cálculo de dominios variables individuales por atributo.

## 5. SQL

SQL es un lenguaje de cuarta generación para definir, consultar, manipular y controlar bases de datos.

### 5.1. Lenguajes SQL

- **DDL:** CREATE, ALTER, DROP, TRUNCATE.
- **DML:** SELECT, INSERT, UPDATE, DELETE, MERGE.
- **DCL:** GRANT y REVOKE.
- **TCL:** COMMIT, ROLLBACK y SAVEPOINT.

### 5.2. Consultas

- `WHERE` filtra filas antes de agrupar.
- `GROUP BY` crea grupos.
- `HAVING` filtra grupos tras agregación.
- `ORDER BY` ordena resultados.
- `DISTINCT` elimina duplicados.
- `UNION` combina resultados y elimina duplicados; `UNION ALL` los conserva.

Ejemplo:

```sql
SELECT provincia, COUNT(*) AS total
FROM empleados
GROUP BY provincia
HAVING COUNT(*) > 20
ORDER BY total DESC;
```

Funciones habituales: COUNT, SUM, AVG, MIN, MAX y LISTAGG. `LISTAGG` concatena valores de varias filas.

### 5.3. JOIN

- `INNER JOIN`: solo coincidencias.
- `LEFT JOIN`: todas las filas de la izquierda y coincidencias de la derecha.
- `RIGHT JOIN`: todas las filas de la derecha.
- `FULL OUTER JOIN`: todas las filas de ambas tablas, con NULL cuando no hay coincidencia.

### 5.4. Vistas y enlaces

Las vistas son consultas almacenadas que pueden ocultar columnas o filas sensibles. No siempre se almacenan físicamente y pueden ser actualizables según su definición.

En Oracle, un **Database Link** permite acceder a datos de otra base de datos.

## 6. Interoperabilidad entre gestores

- **ODBC:** interfaz estándar que permite a aplicaciones conectarse a distintos gestores mediante Driver Manager, drivers y DSN.
- **JDBC:** API Java para acceso uniforme a bases de datos mediante controladores.
- **SQL estándar:** facilita portabilidad, aunque existen extensiones propias.

ODBC no obliga a conocer el almacenamiento físico interno de cada SGBD. El driver traduce llamadas a comandos nativos.

## 7. Oracle y otros SGBD

SGBD comerciales: Oracle Database, SQL Server e IBM Db2. SGBD abiertos: PostgreSQL, MariaDB, MySQL y SQLite.

En Oracle:

- `ALTER TABLE ... ADD (...)` añade columnas;
- `ALTER TABLE ... MODIFY (...)` modifica tipos o tamaños;
- `DROP TABLE` elimina una tabla;
- `SQL*Plus` ejecuta SQL y PL/SQL de forma interactiva o mediante scripts;
- `LISTENER` recibe conexiones de clientes;
- `SHUTDOWN NORMAL`, `IMMEDIATE` y `ABORT` detienen la base con distintos grados de espera;
- `ARCHIVELOG` conserva redo logs para recuperación;
- `RMAN` realiza copias y recuperación;
- `expdp` exporta esquemas y objetos.

El esquema Oracle es el conjunto de objetos que posee un usuario. El puerto habitual del listener Oracle es 1521.

## 8. Resumen para examen

- Una clave candidata es mínima, única y no nula.
- La clave primaria es una candidata elegida.
- Una relación N:M genera tabla intermedia.
- 3FN elimina dependencias transitivas; BCNF exige que todo determinante sea candidato.
- La selección filtra filas; la proyección columnas.
- HAVING filtra grupos y WHERE filas.
- `CREATE` es DDL; `GRANT` es DCL; `COMMIT` es TCL.
- `DISTINCT` elimina duplicados.
- `LEFT JOIN` conserva todas las filas de la tabla izquierda.
- ODBC y JDBC permiten interoperabilidad entre aplicaciones y gestores.
- SQL*Plus ejecuta SQL y PL/SQL.
- RMAN realiza copias y recuperación Oracle.

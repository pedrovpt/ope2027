# **1. Introducción** 

La **arquitectura de los sistemas informáticos** define la estructura y funcionamiento de los componentes de hardware y software en un sistema. En el ámbito sanitario, una **arquitectura eficiente y bien planificada** es esencial para garantizar el acceso rápido y seguro a la información clínica y administrativa en entornos como el **Servicio Andaluz de Salud (SAS)** . 

La **planificación de los sistemas informáticos** considera factores clave como: 

- ✔ **Capacidad** (almacenamiento y procesamiento). 

- ✔ **Rendimiento** (velocidad y eficiencia). 

- ✔ **Flexibilidad** (adaptabilidad a nuevos requerimientos). 

- ✔ **Escalabilidad** (capacidad de crecimiento sin perder eficiencia). 

- ✔ **Alta disponibilidad** (garantía de funcionamiento continuo). 

# **2. Arquitecturas Básicas de los Sistemas Informáticos** 

La arquitectura de un sistema informático define la estructura, organización y funcionamiento de sus componentes principales, incluyendo la unidad central de procesamiento (CPU), la memoria, los dispositivos de entrada/salida y la comunicación entre ellos. Existen diversos tipos de arquitecturas, cada una diseñada para optimizar el rendimiento en función del uso y los requisitos del sistema. 

# **2.1. Tipos de Arquitecturas** 

# **2.1.1. Arquitectura de Von Neumann** 

La arquitectura de **Von Neumann** es el modelo clásico de computación propuesto por John von Neumann en 1945. Se caracteriza por tener una **memoria única** para almacenar tanto instrucciones como datos, lo que implica que el procesador debe acceder a la memoria para obtener ambas cosas. 

**Características:** 

- Usa un **bus único** para la transferencia de datos e instrucciones. 

- La ejecución de instrucciones es **secuencial** , lo que puede generar cuellos de botella en el acceso a memoria. 

- Está compuesta por **unidad de control, unidad aritmético-lógica (ALU), memoria, entrada/salida y bus de datos** . 

# **Ventajas:** 

- Diseño simple y flexible. 

- Reducción de costos de hardware. 

# **Desventajas:** 

- **Cuello de botella de Von Neumann** : la CPU debe esperar a que la memoria le proporcione instrucciones y datos, lo que limita la velocidad de procesamiento. 

# **2.1.2. Arquitectura Harvard** 

En contraste con Von Neumann, la arquitectura **Harvard** separa la memoria de instrucciones y la memoria de datos, permitiendo que la CPU acceda simultáneamente a ambas. 

# **Características:** 

- Uso de **buses separados** para instrucciones y datos, mejorando el rendimiento. 

- Permite la **ejecución en paralelo** de instrucciones y operaciones con datos. 

- Comúnmente utilizada en **microcontroladores y sistemas embebidos** . 

# **Ventajas:** 

- Mayor velocidad de procesamiento al eliminar el cuello de botella de Von Neumann. 

- Mayor seguridad, ya que el código y los datos están en memorias separadas. 

# **Desventajas:** 

- Mayor complejidad y costo de implementación. 

# **2.1.3. Arquitectura Monolítica** 

La arquitectura **monolítica** es un modelo de diseño donde todos los componentes del sistema están unificados en una sola aplicación, funcionando como una única unidad de código. 

# **Características:** 

- Todos los módulos (interfaz de usuario, lógica de negocio y base de datos) están integrados en una misma aplicación. 

- Las funciones del sistema dependen unas de otras dentro de un solo entorno. 

- Es el modelo tradicional en el desarrollo de software antes de la aparición de las arquitecturas orientadas a servicios y microservicios. 

# **Ventajas:** 

- Desarrollo más simple y rápido en sus primeras fases. 

- Fácil de probar y desplegar, ya que todo el sistema se empaqueta como una sola unidad. 

- Menor latencia al no depender de múltiples servicios externos. 

# **Desventajas:** 

- Dificultad para escalar de manera eficiente. 

- La implementación de cambios requiere el despliegue de toda la aplicación nuevamente. 

- Puede volverse difícil de mantener a medida que el sistema crece. 

# **2.1.4. Arquitectura de Cliente-Servidor** 

Este modelo se basa en la comunicación entre **clientes** (dispositivos o aplicaciones que solicitan servicios) y **servidores** (máquinas o programas que procesan las solicitudes y devuelven respuestas). 

**Tipos de arquitecturas cliente-servidor:** 

- **Arquitectura de Dos Capas:** el cliente realiza peticiones directas a la base de datos en el servidor. 

- **Arquitectura de Tres Capas:** introduce un **servidor de aplicaciones** que intermedia entre el cliente y la base de datos. 

- **Arquitectura en N Capas:** el sistema se divide en múltiples capas funcionales, aumentando la modularidad y escalabilidad. 

**Ventajas:** 

- Centralización de recursos y datos en servidores. 

- Fácil administración y mantenimiento. 

# **Desventajas:** 

- Dependencia de la red. 

- Puede requerir una inversión en infraestructura de servidores robustos. 

# **2.1.5. Arquitectura de Sistemas Distribuidos** 

En esta arquitectura, múltiples nodos trabajan en conjunto para proporcionar un servicio, repartiéndose las cargas de trabajo y mejorando la disponibilidad y redundancia. 

# **Ejemplos de sistemas distribuidos:** 

- **Computación en la nube** : múltiples servidores interconectados brindan almacenamiento y procesamiento. 

- **Redes peer-to-peer (P2P)** : cada nodo actúa como cliente y servidor simultáneamente. 

- **Clusters y Grid Computing** : procesamiento en paralelo distribuido en múltiples nodos. 

# **Ventajas:** 

- Escalabilidad y tolerancia a fallos. 

- Distribución eficiente de la carga de trabajo. 

**Desventajas:** 

- Complejidad en la sincronización y gestión de datos. 

- Requiere redes de comunicación de alta velocidad. 

# **2.1.6. Arquitectura de Multiprocesador y Paralela** 

Diseñada para mejorar el rendimiento mediante el uso de múltiples procesadores que trabajan en conjunto. 

# **Tipos de sistemas multiprocesador:** 

- **Simétricos (SMP)** : todos los procesadores comparten la memoria y el sistema operativo distribuye la carga de manera equitativa. 

- **Asimétricos (AMP)** : cada procesador tiene asignadas tareas específicas. 

# **Computación Paralela:** 

- **Procesamiento en paralelo  con múltiples núcleos** . 

- **Arquitecturas SIMD y MIMD** para ejecución simultánea de múltiples instrucciones o flujos de datos. 

# **Ventajas:** 

- Mayor rendimiento en tareas de alto cálculo. 

- Mejora la eficiencia en aplicaciones científicas y análisis de grandes volúmenes de datos. 

# **Desventajas:** 

- Programación más compleja. 

- Requiere sistemas operativos y software optimizados para paralelismo. 

# **2.1.7. Arquitectura Mainframe** 

Los **mainframes** son sistemas centralizados de alto rendimiento diseñados para procesar grandes volúmenes de transacciones simultáneamente. 

**Características:** 

- Alta capacidad de procesamiento y almacenamiento. 

- Soporta múltiples sistemas operativos y usuarios concurrentes. 

- Usado en bancos, seguros y grandes empresas. 

**Ventajas:** 

- Fiabilidad y seguridad en el manejo de datos. 

- Alto rendimiento en entornos empresariales. 

**Desventajas:** 

- Alto costo de implementación y mantenimiento. 

- Requiere personal especializado para su administración. 

# **2.1.8. Arquitectura en la Nube** 

La **arquitectura en la nube** se basa en el uso de **infraestructura y servicios proporcionados por plataformas de computación en la nube** , en lugar de depender de servidores físicos o centros de datos locales. 

**Características:** 

- Los recursos de cómputo, almacenamiento y red se gestionan de forma **dinámica y escalable** . 

- Se accede a través de **Internet** mediante modelos como SaaS (Software as a Service), PaaS (Platform as a Service) e IaaS (Infrastructure as a Service). 

- Permite la distribución geográfica de los datos y servicios. 

**Tipos de despliegue en la nube:** 

1. **Nube pública:** Servicios gestionados por terceros (ejemplo: AWS, Google Cloud, Azure). 

2. **Nube privada:** Infraestructura propia, más segura pero menos escalable. 

3. **Nube híbrida:** Combinación de servicios en la nube pública y privada. 

4. **Nube multi-nube:** Uso de múltiples proveedores de nube para evitar dependencia de un solo proveedor. 

# **Ventajas:** 

- Alta **escalabilidad y flexibilidad** para manejar cargas de trabajo variables. 

- **Reducción de costos** en infraestructura física y mantenimiento. 

- **Mayor disponibilidad y redundancia** mediante sistemas distribuidos. 

**Desventajas:** 

- **Dependencia de proveedores** externos. 

- Posibles **problemas de seguridad y privacidad** al almacenar datos en servidores de terceros. 

- **Latencia** en comparación con sistemas locales, especialmente si los servidores están lejos del usuario. 

# **2.1.9. Arquitectura en Clúster (Cluster Computing)** 

Un **clúster** es un sistema formado por **dos o más sistemas informáticos individuales (nodos), cada uno con su propia CPU, memoria y sistema operativo, acoplados entre sí a través de una red** para trabajar de forma conjunta como si fueran un único sistema, repartiéndose el trabajo o la carga. 

**Características:** 

- Se diferencia de un sistema **multiprocesador** en que este último tiene dos o más procesadores dentro de la misma máquina, compartiendo el bus, el reloj, la memoria y los periféricos; el clúster, en cambio, interconecta equipos completos e independientes (acoplados), cada uno con sus propios recursos. 

- Tipos principales: clúster de **alta disponibilidad** (failover, un nodo asume el trabajo si otro falla), clúster de **balanceo de carga** y clúster de **alto rendimiento** (HPC). 

- Los nodos se comunican mediante una red de interconexión y suelen ser vistos por el usuario o por las aplicaciones como un único recurso. 

**Ventajas:** 

- **Escalabilidad horizontal** : la capacidad se amplía añadiendo nuevos nodos. 

- **Tolerancia a fallos** : si un nodo falla, otro puede asumir su carga de trabajo. 

# **Desventajas:** 

- Mayor complejidad de gestión, configuración y sincronización entre nodos. 

- Coste adicional en infraestructura de red e interconexión entre los nodos. 

# **3. Planificación de los Sistemas Informáticos** 

La planificación de los sistemas informáticos es un proceso estratégico que busca garantizar que la infraestructura tecnológica de una organización pueda satisfacer sus necesidades actuales y futuras. Un plan de sistemas bien diseñado permite optimizar recursos, mejorar el rendimiento, garantizar la disponibilidad de los servicios y anticiparse a los cambios tecnológicos y de negocio. 

La planificación de infraestructuras tecnológicas en entornos críticos como el SAS requiere **evaluar múltiples factores** para garantizar su correcto funcionamiento. 

# **Factores Clave en la Planificación:** 

✔ **Capacidad** : Determina el almacenamiento y procesamiento necesario para datos clínicos y carga de trabajo esperada. 

- ✔ **Rendimiento** : Optimización de tiempos de respuesta de tareas y procesos. 

- ✔ **Flexibilidad** : Adaptabilidad a nuevas tecnologías (IA, Big Data) y a cambios sin grandes modificaciones. 

- ✔ **Escalabilidad** : Expansión y adaptación sin afectar el rendimiento. 

- ✔ **Alta Disponibilidad** : Mecanismos para garantizar continuidad operativa (clústeres, redundancia de datos) incluso ante fallos del sistema. 

La planificación de los sistemas informáticos consiste en diseñar e implementar una infraestructura tecnológica que garantice la eficiencia y disponibilidad de los servicios de TI en una organización. 

# **3.1.1 ¿Por qué es necesaria la planificación de sistemas informáticos?** 

   - Asegura que la infraestructura tecnológica **esté alineada con los objetivos de la organización** . 

   - Permite **anticipar necesidades futuras** y evitar problemas de obsolescencia tecnológica. 

   - Optimiza **costos operativos y de inversión en tecnología** . 

   - Minimiza **fallos y tiempos de inactividad** , garantizando la continuidad del negocio. 

- **3.1.2 Elementos Claves en la Planificación de Sistemas** 

   1. **Evaluación del Estado Actual:** Se analizan los sistemas existentes, su rendimiento, seguridad y capacidad. 

   2. **Definición de Requisitos:** Se identifican las necesidades empresariales y tecnológicas. 

   3. **Análisis de Riesgos:** Se estudian posibles fallos, amenazas y vulnerabilidades. 

   4. **Definición de Arquitectura:** Se eligen los modelos de infraestructura adecuados (monolítica, distribuida, en la nube, etc.). 

   5. **Estrategia de Implementación:** Se planifican las fases de desarrollo, pruebas y despliegue. 

6. **Monitoreo y Mantenimiento:** Se establecen métricas y procedimientos para la supervisión del sistema. 

# **3.2 Capacidad** 

La **capacidad** de un sistema informático se refiere a su habilidad para manejar una carga de trabajo específica dentro de un período de tiempo determinado. Esto incluye: 

- La cantidad de usuarios simultáneos que puede soportar. 

- La capacidad de almacenamiento y procesamiento de datos. 

- La capacidad de la red y sus tiempos de respuesta. 

# **3.2.1 Planificación de la Capacidad** 

El proceso de planificación de la capacidad se basa en: 

   1. **Análisis de demanda actual y futura** (usuarios, datos, procesamiento). 

   2. **Identificación de cuellos de botella** que afecten la eficiencia del sistema. 

   3. **Estimación de crecimiento** en función de proyecciones de negocio. 

   4. **Implementación de medidas de optimización** , como balanceo de carga o ampliación de recursos. 

- **3.2.2 Importancia de la Planificación de Capacidad** 

   - Evita la sobrecarga del sistema. 

   - Permite una mejor distribución de los recursos. 

   - Mejora la experiencia del usuario al reducir tiempos de espera y fallos. 

# **3.3 Rendimiento** 

El **rendimiento** mide la eficiencia con la que un sistema ejecuta procesos y maneja solicitudes. Se evalúa en función de la velocidad, la latencia y la capacidad de procesamiento. 

# **3.3.1 Factores que Afectan el Rendimiento** 

- **Capacidad del procesador (CPU)** : Afecta la velocidad de ejecución de tareas. 

- **Memoria RAM y almacenamiento** : Determinan la rapidez en la carga y recuperación de datos. 

- **Ancho de banda de red** : Influye en la velocidad de transmisión de datos. 

- **Optimización del software** : Un código mal optimizado puede generar retardos innecesarios. 

# **3.3.2 Medición del Rendimiento** 

Existen varias métricas para evaluar el rendimiento de un sistema: 

- **Tiempo de respuesta** : Tiempo que tarda el sistema en procesar una solicitud. 

- **Throughput** : Cantidad de transacciones o procesos completados por unidad de tiempo. 

- **Latencia** : Tiempo de retraso entre una solicitud y su ejecución. 

- **Índices MIPS y MFLOPS** : Evalúan el número de instrucciones procesadas por segundo. 

# **3.3.3 Métodos de Evaluación del Rendimiento** 

- **Pruebas de carga** : Simulan usuarios concurrentes para evaluar el desempeño. 

- **Pruebas de estrés** : Llevan el sistema a su límite para medir su capacidad máxima. 

- **Pruebas de estabilidad** : Evalúan el comportamiento del sistema bajo carga prolongada. 

# **3.4 Flexibilidad** 

La **flexibilidad** de un sistema informático se refiere a su capacidad para adaptarse a cambios en los requisitos sin grandes modificaciones estructurales. 

# **3.4.1 Características de un Sistema Flexible** 

- **Modularidad** : Permite cambiar o agregar componentes sin afectar todo el sistema. 

- **Compatibilidad** : Soporte para diversas plataformas y tecnologías. 

- **Interoperabilidad** : Capacidad para integrarse con otros sistemas. 

- **Personalización** : Ajustes según las necesidades del negocio. 

# **3.4.2 Beneficios de la Flexibilidad** 

- Facilita la actualización tecnológica sin grandes costos. 

- Permite responder rápidamente a cambios en el mercado. 

- Reduce tiempos de implementación de mejoras. 

# **3.5 Escalabilidad** 

La **escalabilidad** es la capacidad del sistema para crecer en capacidad de procesamiento y almacenamiento sin perder rendimiento. 

# **3.5.1 Tipos de Escalabilidad** 

1. **Escalabilidad Vertical** (Scale-Up): Aumentar los recursos en un solo servidor (más CPU, RAM, almacenamiento). 

2. **Escalabilidad Horizontal** (Scale-Out): Agregar más servidores o nodos para distribuir la carga de trabajo. 

# **3.5.2 Ejemplos de Escalabilidad** 

- **Bases de datos distribuidas** para soportar mayor tráfico de consultas. 

- **Sistemas en la nube** , que permiten agregar o reducir recursos dinámicamente. 

# **3.5.3 Desafíos de la Escalabilidad** 

- Equilibrio entre **costos** y **rendimiento** . 

- **Coherencia de datos** en sistemas distribuidos. 

- **Latency y sincronización** en múltiples servidores. 

# **3.6 Alta Disponibilidad** 

La **alta disponibilidad (HA, High Availability)** se refiere a la capacidad del sistema para funcionar sin interrupciones, minimizando el tiempo de inactividad. 

# **3.6.1 Elementos de Alta Disponibilidad** 

1. **Redundancia** : Duplicación de servidores y datos para evitar pérdida de información. 

2. **Balanceo de carga** : Distribuye solicitudes entre múltiples servidores. 

3. **Sistemas de recuperación ante fallos** : Métodos de respaldo y recuperación automática. 

4. **Monitoreo continuo** : Detección temprana de errores para prevenir caídas. 

# **3.6.2 Técnicas para Garantizar Alta Disponibilidad** 

- **Clústeres de servidores** con failover automático. 

- **Copias de seguridad y recuperación ante desastres (Disaster Recovery)** . 

- **Sistemas de almacenamiento RAID** para evitar pérdida de datos. 

# **3.6.3 Granjas de Servidores (Web Farms) y Balanceo de Carga** 

Una **granja de servidores (web farm)** es un conjunto de servidores que trabajan de forma conjunta para atender las peticiones de una misma aplicación o sitio web, repartiendo la carga entre ellos como técnica de alta disponibilidad y escalabilidad. 

# **Ventajas de las granjas de servidores:** 

- Liberan al usuario final de tener que saber qué servidor concreto está procesando su petición. 

- Reducen el riesgo de errores de operación, mejorando la fiabilidad y la disponibilidad percibidas por los usuarios finales. 

- Simplifican las actualizaciones del sistema: pueden aplicarse de forma escalonada ( _rolling update_ ) mientras el resto de servidores de la granja siguen repartiéndose el acceso a los recursos, sin necesidad de detener el servicio. 

- **No minimizan el coste** de la instalación web; al contrario, requieren invertir en más servidores, balanceadores de carga y en su mantenimiento. 

# **Balanceo de carga con NLB:** 

En los sistemas **Windows Server** , el **NLB (Network Load Balancing, balanceo de carga de red)** es la funcionalidad que permite implementar una granja de servidores, distribuyendo automáticamente el tráfico entrante entre los distintos nodos del clúster de NLB para mejorar el rendimiento y la disponibilidad del servicio. 

# **3.6.4 Métricas de la Alta Disponibilidad** 

Para cuantificar la alta disponibilidad de un sistema de información se emplean, entre otras, las siguientes métricas: 

- **MTBF (Mean Time Between Failures, Tiempo Medio Entre Fallos):** tiempo medio que transcurre entre dos fallos consecutivos de un componente o sistema; cuanto mayor es su valor, más fiable es el sistema. 

- **MTTR (Mean Time To Repair, Tiempo Medio de Reparación):** tiempo medio necesario para reparar un fallo y restaurar el servicio tras una incidencia. 

- **Porcentaje de disponibilidad (uptime):** porcentaje del tiempo total en que el sistema está operativo; por ejemplo, el conocido "cinco nueves" (99,999%) equivale a poco más de 5 minutos de inactividad al año. 

# **4. Unidades Centrales Multiusuario** 

Una unidad central multiusuario es un sistema informático con una **unidad central de procesamiento (CPU)** y **recursos compartidos** , que da servicio simultáneo a múltiples usuarios, generalmente a través de **terminales conectadas a través de una red** o directamente a la máquina. 

Estos sistemas están controlados por **sistemas operativos multiusuario** (como UNIX, Linux, z/OS), que gestionan el uso compartido de los recursos del hardware, asegurando que cada usuario tenga la impresión de trabajar de forma independiente. 

El término “multiusuario” no se refiere solo a la capacidad de tener múltiples cuentas de usuario, sino a la **habilidad real de gestionar procesos, almacenamiento y memoria para distintos usuarios al mismo tiempo** , asegurando eficiencia, seguridad y rendimiento. 

# **4.1 Características Principales** 

# **1. Multiprogramación** 

Capacidad para **ejecutar varios programas a la vez** . El sistema operativo alterna entre tareas, asignando el uso del procesador a cada una durante periodos cortos (timesharing). 

# **2. Acceso concurrente** 

Múltiples usuarios pueden **acceder a los mismos recursos físicos y lógicos** (procesador, memoria, almacenamiento, impresoras), con mecanismos de control que evitan interferencias. 

# **3. Planificación de procesos** 

El sistema operativo incluye algoritmos de planificación (round robin, prioridades, etc.) que **asignan eficientemente los recursos de CPU** entre usuarios y tareas. 

# **4. Gestión de memoria compartida** 

Los procesos de los distintos usuarios comparten memoria de forma controlada. Se utilizan técnicas como la **segmentación** y la **paginación** para garantizar el acceso seguro y eficiente. 

# **5. Seguridad y aislamiento** 

Cada usuario accede con su perfil y permisos, manteniendo **aislamiento entre los procesos** , protegiendo tanto los datos como la ejecución del sistema frente a errores o accesos indebidos. Sistema de permisos y seguridad avanzada. 

# **6. Soporte a periféricos compartidos** 

Impresoras, escáneres, unidades de almacenamiento y otros dispositivos pueden ser compartidos por los usuarios, mediante **colas de impresión** o sistemas de control de acceso concurrente. 

# **7. Acceso remoto** 

Los usuarios pueden conectarse desde **terminales remotas** , ya sea físicas (como terminales “tontas” en entornos mainframe) o lógicas (acceso vía red usando SSH, telnet, escritorio remoto, etc.). 

# **Ejemplos:** 

- **Mainframes** utilizados en banca, administración pública o grandes empresas, con cientos o miles de usuarios accediendo simultáneamente. 

- **Servidores UNIX/Linux** que proporcionan servicios web, bases de datos o aplicaciones a múltiples usuarios. 

- **Entornos virtualizados o en la nube** , donde una máquina virtual puede ser accedida por múltiples usuarios concurrentes. 

- **Centros educativos o laboratorios** con terminales conectadas a un servidor central. 

# **Ejemplo en el SAS:** 

El **Sistema de Información Hospitalaria** permite que médicos, enfermeros y administrativos accedan a la información clínica en tiempo real. 

# **4.3 Tecnologías Relacionadas** 

# **DMA (Direct Memory Access)** 

El uso de **acceso directo a memoria** permite que los dispositivos periféricos interactúen con la memoria sin intervención constante de la CPU, **liberando carga del procesador** y mejorando la eficiencia en entornos multiusuario. 

# **Sistemas Operativos Multiusuario** 

- **UNIX/Linux** : Soportan múltiples usuarios concurrentes con estructuras de permisos y aislamiento robustas. 

- **z/OS (IBM)** : Usado en mainframes, proporciona partición lógica y ejecución segura de procesos multiusuario. 

- **Windows Server** : También soporta entornos multiusuario, especialmente en configuraciones de escritorio remoto o terminal services. 

# **4.4 Ventajas de las Unidades Centrales Multiusuario** 

- **Aprovechamiento eficiente de los recursos** : la CPU y la memoria son compartidas, reduciendo costes. 

- **Escalabilidad** : pueden crecer en número de usuarios o potencia. 

- **Centralización** : los datos y programas se mantienen en el servidor, facilitando la administración y seguridad. 

- **Reducción de costes** : al evitar la necesidad de múltiples equipos completos por usuario. 

- **Acceso simultáneo y colaborativo** a la información. 

# **5. Evolución y Tendencia de las Unidades Centrales Multiusuario** 

Las unidades centrales multiusuario han evolucionado de sistemas centralizados con terminales conectadas a potentes mainframes, a complejas infraestructuras distribuidas y virtualizadas que operan en la nube. Este cambio ha sido impulsado por la necesidad de mejorar la eficiencia, reducir costes, y facilitar el acceso remoto y concurrente a los sistemas. 

Hoy, el paradigma multiusuario se mantiene vigente en **servidores, entornos cloud, sistemas de virtualización y contenedores** , adaptándose a nuevos modelos de consumo de servicios informáticos como el **modelo “as-a-service” (SaaS, PaaS, IaaS)** . 

# **5.1 Evolución Histórica** 

# **1. Sistemas Centralizados (décadas 60 y 70)** 

- Se usaban **mainframes** o **minicomputadoras** . 

- Los usuarios accedían mediante **terminales tontas** conectadas a una única unidad central. 

- Los sistemas operativos multiusuario (como **UNIX** , creado en 1969) gestionaban múltiples sesiones simultáneas. 

- Ejemplo: IBM System/360. 

# **2. Tiempo Compartido y Multiprogramación** 

- Aparecen los sistemas **de tiempo compartido (time-sharing)** que permitían a múltiples usuarios trabajar simultáneamente con una CPU que alternaba rápidamente entre procesos. 

- La **multiprogramación** permitía mantener varias tareas en memoria, mejorando el aprovechamiento de recursos. 

# **3. Arquitecturas Cliente-Servidor (años 80 y 90)** 

- Las estaciones de trabajo comenzaron a tener más capacidad, y surgió el modelo **cliente-servidor** . 

- El servidor actúa como unidad central multiusuario, mientras que los clientes (PCs o terminales) solicitan servicios (correo, impresión, bases de datos, etc.). 

- Se reduce la carga del servidor con **procesamiento distribuido** . 

# **4. Virtualización y Consolidación de Servidores (años 2000)** 

- Aparecen tecnologías como **VMware, Xen, Hyper-V** , que permiten ejecutar múltiples **máquinas virtuales (VMs)** en una misma unidad central. 

- Cada VM puede albergar múltiples usuarios. 

- Se mejora el uso de recursos y se reduce el número de servidores físicos. 

# **5. Computación en la Nube (2010 en adelante)** 

- Las unidades centrales multiusuario ahora residen en **infraestructuras cloud (Amazon Web Services, Microsoft Azure, Google Cloud)** . 

- Los usuarios acceden a servicios compartidos desde cualquier lugar, con una gestión automática de recursos, escalado y alta disponibilidad. 

- El hardware físico es abstracto; los recursos se consumen **bajo demanda** . 

# **5.2 Tendencias Actuales** 

# **1. Infraestructura como Servicio (IaaS)** 

- Proveedores como AWS o Azure ofrecen **instancias virtuales multiusuario** , escalables y gestionadas dinámicamente. 

- El concepto de “unidad central” se transforma en un recurso **virtualizado y compartido globalmente** . 

# **2. Contenedores y Microservicios** 

   - Tecnologías como **Docker y Kubernetes** permiten ejecutar aplicaciones aisladas, pero compartiendo el mismo kernel del sistema operativo. 

   - Un servidor físico puede ejecutar cientos de contenedores, cada uno con múltiples sesiones o procesos simultáneos. 

**3. Edge Computing y Descentralización** 

   - Para reducir latencia, se está llevando el procesamiento multiusuario a la **periferia de la red** (edge), como en dispositivos IoT, routers o centros de datos regionales. 

**4. Inteligencia Artificial y Automatización** 

   - Las unidades centrales incorporan **gestión automática de carga** , **balanceo inteligente** y **ajuste dinámico de recursos** mediante algoritmos de IA. 

   - Esto permite atender a miles de usuarios con eficiencia energética y de rendimiento. 

# **5. Arquitecturas Serverless** 

- Se evoluciona hacia modelos donde **no se gestionan unidades centrales directamente** . El proveedor ejecuta el código del usuario en función de eventos, sin preocuparse por la infraestructura. 

# **5.3 Desafíos y Consideraciones Futuras** 

- **Ciberseguridad** : más usuarios conectados implica mayores riesgos. 

- **Garantías de privacidad** y control de accesos más avanzados. 

- **Sostenibilidad** : centros de datos deben ser eficientes energéticamente. 

- **Mayor dependencia de la conectividad global** . 

# **6. Sistemas Departamentales y Grandes Sistemas Centrales** 

En el ámbito de los sistemas informáticos, es común distinguir entre **sistemas departamentales** y **grandes sistemas centrales** (también conocidos como _mainframes_ ). Ambos tipos de sistemas son fundamentales para las organizaciones, pero difieren en términos de **capacidad, escalabilidad, uso previsto, coste y complejidad** . 

Mientras los sistemas departamentales se utilizan en áreas concretas o pequeñas unidades organizativas, los grandes sistemas centrales soportan operaciones críticas a gran escala y a menudo están en el corazón del procesamiento de datos de grandes empresas y organismos públicos. 

# **6.1 Sistemas Departamentales** 

# **Definición** 

Un **sistema departamental** es un sistema informático que **atiende a una unidad o departamento específico** dentro de una organización (por ejemplo, contabilidad, recursos humanos, logística, farmacia hospitalaria, etc.). Su objetivo es **resolver necesidades concretas de procesamiento y gestión de información a nivel local** . 

# **Características:** 

- Menor capacidad de procesamiento que los mainframes. 

- Normalmente son **servidores de gama media** o incluso estaciones de trabajo avanzadas. 

- Utilizan sistemas operativos como **Windows Server, Linux o Unix** . 

- Pueden estar **conectados a un sistema central** o funcionar de manera independiente. 

- Suelen ofrecer servicios como bases de datos locales, gestión documental, correo interno o aplicaciones específicas del área. 

# **Ventajas:** 

- **Flexibilidad** : pueden personalizarse para el área en la que se utilizan. 

- **Menor coste de adquisición y mantenimiento** . 

- **Descentralización del procesamiento** , reduciendo la carga sobre los sistemas centrales. 

- **Mayor optimización de recursos.** 

- **Mayor especialización de tareas.** 

# **Limitaciones:** 

- **Menor capacidad de escalado** . 

- Mayor **dificultad para integrar y consolidar datos** entre departamentos. 

- Posible **duplicación de información y procesos** si no se coordina bien con el sistema central. 

# **6.2 Grandes Sistemas Centrales (Mainframes)** 

# **Definición** 

Los **mainframes** son **grandes computadoras centralizadas** capaces de ejecutar millones de transacciones simultáneamente, con **altos niveles de fiabilidad, disponibilidad y seguridad** . Se utilizan para gestionar **volúmenes masivos de datos y procesos críticos** . 

**Usos comunes:** 

- Banca y finanzas: procesamiento de transacciones, gestión de cuentas. 

- Administraciones públicas: historia clínica electrónica, bases de datos ciudadanas. 

- Telecomunicaciones: gestión de redes, facturación masiva. 

- Grandes empresas: ERP, CRM, nóminas y logística global. 

# **Características:** 

- Soportan **miles de usuarios concurrentes** . 

- Alta tolerancia a fallos, redundancia y **disponibilidad continua (24/7)** . 

- Capacidad para manejar **transacciones en tiempo real** y procesamiento batch. 

- Utilizan sistemas operativos como **z/OS, z/VM, Linux for System z** (en IBM) o **Unisys OS2200** . 

- Alto rendimiento y capacidad de procesamiento. 

# **Ventajas:** 

- **Fiabilidad extrema** : diseñados para no fallar. 

- **Escalabilidad vertical** : se pueden ampliar sin rediseñar la arquitectura. 

- **Seguridad robusta** y control de accesos multiusuario. 

- **Integración con sistemas legacy** . 

# **Desventajas:** 

- **Coste elevado** de adquisición, mantenimiento y personal especializado. 

- **Complejidad operativa** : requieren administración avanzada. 

- **Poca flexibilidad** comparada con entornos en la nube. 

# **6.4 Comparativa entre ambos sistemas** 

|**Característica**|**Sistemas Departamentales**|**Grandes Sistemas Centrales**<br>**(Mainframes)**|
|---|---|---|
|**Alcance**|Departamento o unidad<br>específica|Toda la organización o<br>múltiples regiones|
|**Escalabilidad**|Limitada|Muy alta|
|**Costo**|Moderado|Alto|
|**Usuarios**<br>**concurrentes**|Decenas|Miles o más|
|**Disponibilidad**<br>**requerida**|Media|Muy alta (99.999%)|
|**Procesamiento**|Transacciones de bajo/medio<br>volumen|Procesamiento masivo y crítico|
|**Mantenimiento**|Técnico generalista|Personal especializado|



# **Ejemplo en el SAS:** 

El sistema **Diraya** utiliza una arquitectura centralizada para gestionar historias clínicas electrónicas en toda Andalucía. 

# **6.5 Tendencias Actuales** 

- **Integración híbrida** : muchas organizaciones utilizan **mainframes como núcleo** y sistemas departamentales conectados mediante **APIs o middleware** . 

- **Virtualización y contenedores** : tecnologías como **Docker o z/VM** permiten crear entornos aislados dentro del mismo sistema físico. 

- **Mainframes en la nube** : IBM y otros fabricantes están **adaptando sus mainframes a modelos cloud** , combinando su potencia con flexibilidad y escalabilidad on-demand. 

- **Descentralización inteligente** : se promueve un modelo donde los sistemas departamentales procesan localmente, pero **sincronizan la información con sistemas centrales** en tiempo real.
